agentplay: локальный просмотрщик сессий Claude Code, Codex и других агентов в виде карты и таймлайна

agentplay (Entelligence-AI, Apache-2.0, репозиторий создан 14 октября 2026, 151 звезда) читает локальные логи сессий агентов (~/.claude, ~/.codex, ~/.cursor) и открывает в браузере на http://127.0.0.1:7317/ два вида. Карта — радиальное дерево: репозитории, файлы, shell-команды, MCP-серверы, субагенты, ошибки, модели, результаты вроде коммитов и PR. Таймлайн — проигрывание на 1x/4x/16x с перемоткой и дорожками для промптов, ошибок, правок, токенов, стоимости и компакций. Горячие клавиши E/X/D/O/R прыгают к правкам, ошибкам, задержкам, результатам и ретраям; есть вкладка Errors и фильтр по задаче, модели или субагенту. Поддерживаются Claude Code (лучшая детализация, дорожки субагентов), Codex, Cursor, Copilot CLI, Copilot в VS Code, OpenCode, Kiro; у остальных только основная дорожка. Python 3.11+, без зависимостей. По README данные не уходят с машины, телеметрии нет, а в карте нет текста промптов, содержимого файлов и аргументов команд (shell хранится только глаголом). Ограничения: стоимость — оценка по публичным прайсам, сессия до 20 000 событий, транскрипты больше 512 МБ пропускаются, Write не всегда отличает создание от перезаписи.

У вас уже есть скилл observability и Workflow с вложенными лидами, но это анализ, а не визуальный разбор. Здесь новое — посмотреть, где в многоагентном прогоне были ретраи, ошибки и задержки, какие MCP-серверы реально вызывались и как росла стоимость до компакций. Первый шаг: `uvx agentplay` (или `pipx run agentplay`), затем `agentplay list --agents claude --since` с нужным периодом, чтобы открыть сессию с Workflow или нескольких субагентов.

Что взять себе
  • Прогнать `uvx agentplay` по последней сессии с Workflow и субагентами и найти ретраи и задержки — добавить результаты в скилл observability как источник?
  • Проверить через вкладку Errors и узлы MCP на карте, какие из MCP-серверов (codebase-memory, Telegram, Chrome) реально вызываются, и убрать неиспользуемые из always-loaded конфига в рамках settings-cleanup?
  • Использовать дорожки токенов, стоимости и компакций, чтобы найти момент, где сессия бота в Telegram раздувается, и подстроить правила в CLAUDE.md?

Вышел OpenCode 2.0: фоновый сервис, Code Mode для MCP, фоновые субагенты и горячая перезагрузка плагинов

OpenCode 2.0 — крупное обновление open-source кодового агента. Сервер теперь всегда крутится одним фоновым процессом на машине, к нему подключаются TUI, веб и десктоп; доступ с других хостов — через /pair или opencode pair. API переписан с нуля, агент может вызывать его сам (worktree_create, session_move, session_prompt, session_interrupt и т.д.); есть пакет @opencode/client и @opencode/sdk (тот же код, что в CLI, можно встроить в свой сервер).

Главное новое — Code Mode (@opencode/codemode): минимальный JS-интерпретатор превращает MCP-серверы и OpenAPI в функции, и модель пишет один скрипт «вызвать инструмент → обработать → вызвать другой» вместо цепочки отдельных вызовов. Все MCP по умолчанию включены в этот режим, автор говорит, что можно подключить тысячу серверов без раздувания контекста. Ещё: фоновые субагенты (в том числе на другой модели), фоновые shell-команды, Ctrl+B переводит медленную команду или субагента в фон; 80+ внутренних плагинов, всё горячо перезагружается, так что агент может написать плагин для себя посреди сессии. Минусы: планы 1.0 не работают, серверный API другой. По обсуждению на HN: плагинные инструменты якобы игнорируют настройки permissions, для песочницы нужен --standalone, жалобы на RAM и зависания.

У тебя уже есть Workflow, фоновые агенты, хуки, MCP и claude -p; новое — Code Mode и постоянный локальный сервис с API. Первый шаг: на тестовой машине обновить 1.x и выполнить opencode upgrade --major, затем подключить пару MCP и посмотреть, как Code Mode сократит число вызовов.

Что взять себе
  • Code Mode: при многошаговых MCP-цепочках (Google Workspace, Telegram) пробовать паттерн «одним скриптом вместо серии вызовов» — оценить в opencode, нужен ли такой слой для наших MCP-серверов
  • Добавить в cross-vendor review скилл проверку: opencode 2.0 с --standalone как песочница для ревью, учитывая жалобы на обход permissions у плагинных инструментов
  • Попробовать opencode api / @opencode/client для запуска по расписанию как альтернативу claude -p в скриптах — сравнить удобство

03Claude Code releases14.10

Claude Code 2.1.300: хуки для модов, кэш-токены в OTel, строгая проверка updatedInput

Релиз 2.1.300 от 14.10.2026 — в основном фиксы, но есть несколько вещей для тех, кто строит поверх Claude Code. Для модов: хук `agent.spawn` теперь умеет переписывать `prompt` и `model` у агентов Workflow (раньше мог только отказать), новый хук `prompt.change` (срабатывает, когда текст в промпте изменился не набором: история, очистка, undo, заполнение плагином), `virtualText` в декорациях промпта и `$.ui.view({ agentId })` для показа транскрипта агента в главном окне. В OpenTelemetry событие `api_request` получило `cache_creation_5m_tokens` и `cache_creation_1h_tokens` (запись кэша по сроку жизни), а в спаны добавлены атрибуты GenAI: `gen_ai.provider.name`, `gen_ai.conversation.id`, `gen_ai.tool.name`, `error.type`.

Изменения поведения: `updatedInput` из хуков PreToolUse и PermissionRequest теперь валидируется как родной ввод инструмента — неизвестные ключи отбрасываются, а отклонённый инструментом ввод запрещает вызов. Хуки агентов теперь уважают свой `model` (алиасы вроде `haiku` работают, недоступная модель уходит на модель вызывающего). SessionEnd-хуки надёжнее срабатывают при выходе с фоновой командой, а сами фоновые команды убиваются через 1,5 с. Фоновые сессии продолжают перенесённый workflow через одобрение инструмента Workflow. Починено: `ENABLE_TOOL_SEARCH=auto` выключался посреди диалога, `--worktree` стартовал не с того коммита, пропадали подагенты в `/tasks`. Транскрипты теперь пишут system prompt, tools и параметры каждого запроса. Появилась `CLAUDE_CODE_GZIP_REQUEST_BODIES=0` для отключения gzip.

Для твоей схемы: у тебя много хуков PreToolUse и работа с worktree, поэтому проверь, что твои `updatedInput` не содержат лишних ключей — иначе вызов теперь будет отклонён. Первый шаг: обнови Claude Code и прогони хуки, которые меняют ввод инструментов.

Что взять себе
  • Прогнать все PreToolUse/PermissionRequest хуки, которые отдают `updatedInput`, и убрать из него лишние ключи — теперь неизвестные ключи отбрасываются, а отклонённый ввод запрещает вызов.
  • Вывести `cache_creation_5m_tokens` и `cache_creation_1h_tokens` в скилл observability, чтобы видеть, сколько уходит на запись кэша по сроку жизни.
  • Если используешь Workflow с моды: попробовать хук `agent.spawn` для подмены `model` и `prompt` у воркфлоу-агентов, например дешёвая модель для мелких шагов.

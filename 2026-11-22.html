Thinking Machines выпустила открытую Inkling 2 Mini: MoE на 26.4B с циклом слоёв, 20 ГБ, запускается на ноутбуке

Thinking Machines Lab 20 ноября 2026 опубликовала Inkling 2 Mini с открытыми весами. Это MoE на 26.4B параметров (3.4B активных), «зацикленный» трансформер: средние слои прогоняются три раза на токен, так что из 24 хранимых слоёв получается 48 применений. Модель думает глубже, не печатая больше токенов. Память около 20 ГБ, обучение и инференс в основном в NVFP4.

Цифры из статьи (самоотчёт): SWE-bench Verified 79.2%, SWE-bench Pro v2 Hard 77.9%, Terminal Bench v2.1 71.6%, MCP Atlas 82.7%, BrowseComp 79.0% (с компактификацией). Лидер среди открытых моделей до 100B на DeepSWE v1.1 (48.2%). Слабые места: многоходовой чат и инструкции с множеством ограничений (MultiChallenge 50.0%, ComplexConstraints 33.4%, ниже Qwen3.8-27B), знания фактов на уровне моделей того же размера, поэтому ставка на поиск и тулы. Внутренний замер деструктивных действий: 10.2%.

Для твоего сетапа: основной агент остаётся на Opus/Sonnet 5.5, но это кандидат на локальную дешёвую модель для массовых подзадач (суммаризация, извлечение, тул-вызовы) рядом с MLX-моделями. Цена и API в статье не указаны. Первый шаг: на Mac с 32+ ГБ RAM поднять через Ollama (поддержка заявлена, точных команд нет) или квантованный GGUF от Unsloth через llama.cpp и прогнать на своих задачах с `claude -p --json-schema`.

Что взять себе
  • Скачать квантованный GGUF (Unsloth) или Ollama-версию и прогнать на 5-10 реальных задачах из наших скриптов с `claude -p --json-schema`, сравнив с текущей локальной MLX-моделью.
  • Добавить Inkling 2 Mini как кандидата в cross-vendor review и в роль дешёвого исполнителя для суммаризации и извлечения, где сейчас идёт Gemini/Antigravity или Haiku.
  • Для тул-ориентированных задач проверить её на наших MCP-серверах (codebase-memory, Telegram): в статье заявлено MCP Atlas 82.7%, но слабые инструкции со многими ограничениями, так что промпты держать короткими.

02Hacker News21.11

Inkling-2-Mini (26.4B MoE) сжали до 5.4 ГБ для Apple Silicon: HumanEval 71% против 93% у оригинала

LookAtMyQuant — набор MLX-квантизаций модели thinkingmachines/Inkling-2-Mini: MoE на 26.4B параметров, 5.4B активных, 128 экспертов с top-8, слои 6–17 прогоняются трижды. Текстовые веса в BF16 занимают 18.89 ГБ, авторы сделали шесть сборок от 3.9 до 12.8 ГБ. Сборка на 5.4 ГБ — это 1.65 бита на вес, метод «SQYFR v2»: эксперты и 130–144 attention-проекций обучаются совместно на ответах учителя, плюс финальная подгонка масштабов.\n\nРезультаты против BF16: GSM8K 87.0% против 96.5%, HumanEval 71.3% против 92.7%, vision 4/4. На Apple M5 Max: префилл 1807 tok/s, декод 75.3 tok/s, с драфтером (около 179 МБ) медианно 124.4 tok/s, активная память 5.33 ГБ. Ограничения: код заметно просел, выборки малые (200, 164 и 4 задачи), лицензия на веса в README не указана, MIT только у кода.\n\nДля тебя это не про Claude Code, а про локальные модели на MLX: уже есть, но для кода 71% HumanEval слабоват, годится скорее для дешёвых задач вроде суммаризации или извлечения. Первый шаг: pip install git+https://github.com/ShinMegamiBoson/lookatmyquant.git, затем lamq generate shinmegamiboson/Inkling-2-Mini-LookAtMyQuant-5.4GB --drafter shinmegamiboson/Inkling-2-Mini-LookAtMyQuant-drafter -p "..." --stats.

Что взять себе
  • Прогнать 5.4GB-сборку через lamq с --stats на твоём Mac и сравнить tok/s и качество с текущими локальными MLX-моделями.
  • Использовать её только для дешёвых фоновых задач (суммаризация, извлечение), а не для кода: HumanEval 71.3% против 92.7%.
  • Перед использованием проверить лицензию весов на Hugging Face: в README её нет.

03Hacker News20.11

OpenComputer: open-source (Apache 2.0) аналог Devin — @Computer в Slack запускает Claude Code/Codex/OpenCode на своей VM и отдаёт PR

diggerhq выложили OpenComputer: пишешь @Computer в треде Slack, агент работает на своей «машине», команда может смотреть и править ход работы, результат приходит как pull request. Своего агента нет: внутри запускаются твои Claude Code, Codex или OpenCode (можно со своей подпиской ChatGPT/Codex). Архитектура: одна VM (минимум одна на организацию) с шлюзом «Calvin», каждая сессия изолирована rootless Podman; состояние пишется на локальный диск и после каждого хода бэкапится в git, так что сессию можно продолжить на другой VM. Slack-события принимают Cloudflare Workers и Durable Objects, VM сама подключается по websocket, нужен только исходящий трафик. Есть web UI, CLI, API. Лимиты: только Slack (Discord и T3 Code в планах), self-host только в облаке команды (AWS/GCP/Azure, см. SELFHOSTING.md), зависимость от Cloudflare; локальные модели не поддерживаются. Бенчмарки авторов (PR в 3.3 раза быстрее Devin: 56 с против 185 с; первый push 24 с против 62 с) никем не проверены. Облако: 3 дня бесплатно, 600 минут работы.

Для тебя это не новый инструмент, а паттерн: Claude Code как серверный воркер в чате команды. Свой Claude Code в Telegram-боте у тебя уже есть, так что ценность в деталях: песочница на Podman и снапшот состояния сессии в git после каждого хода. Первый шаг: открыть SELFHOSTING.md в github.com/diggerhq/opencomputer и посмотреть, как устроены сессия и её восстановление. Запускать целиком не обязательно.

Что взять себе
  • Из OpenComputer: после каждого хода бэкапить состояние сессии бота в git, чтобы продолжать на другой машине. Добавить такое в bot-session.sh?
  • Изолировать сессии Telegram-бота в rootless Podman, как у OpenComputer, вместо общего окружения. Посмотреть?

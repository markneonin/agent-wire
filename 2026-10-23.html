01Codex CLI releases23.10

Codex CLI 0.164.0: слоты /presets, аргументы у /model и /permissions, маскировка секретов

В релизе rust-v0.164.0 Codex CLI появились десять нумерованных слотов /presets: в них сохраняются повторяющиеся промпты и слэш-команды, а вызываются они клавиатурным меню (#54380, #54381). /model и /permissions теперь принимают inline-аргументы: модель, reasoning effort, скорость и permission-профиль задаются одной командой (#54378, #54383). Картинки можно смотреть в полноэкранном транскрипте в терминалах с Kitty или Sixel (#54216).

Ещё в релизе: маскировка credentials в удалённых сессиях Bash/Zsh, включая custom providers (#54309, #54432, #56049). Если маскировка недоступна, unified exec может откатиться на обычный режим (#55719). MCP OAuth-refresh теперь координируется по умолчанию (#55701). Для корпоративных аккаунтов добавлена авторизация MCP через гранты аккаунта Codex. Исправления: неудачная компакция не оставляет частичных саммари в истории (#53932, #55581), resume находит сжатые истории и восстанавливает настройки треда (#54008, #55923), `-c/--config` сохраняется на нескольких уровнях субкоманд (#56022), очередь промптов ждёт выбора разрешений (#55682). Усилены sandbox-проверки на macOS для путей, различающихся регистром, и для заменяемых симлинков. Флаги worktree и voice, а также transcript_v2 удалены.

Для твоего сетапа Codex — второе мнение в vendor-review и use-codex. Новое здесь в основном то, что можно подстроить под headless-вызовы: inline-аргументы /model и /permissions и более надёжный `-c` в субкомандах. Первый шаг: обновить Codex и в интерактивной сессии выполнить /model с аргументами, затем сохранить в /presets пару промптов для ревью. Точный синтаксис аргументов сверь в самих командах, в заметках релиза он не приведён.

Что взять себе
  • Обновить Codex до 0.164.0 и проверить, что `-c/--config` теперь держится в субкомандах: это может упростить вызовы в скилле use-codex.
  • Сохранить в /presets Codex два-три промпта для cross-vendor ревью, чтобы вызывать их из меню, а не печатать заново.
  • Проверить в vendor-review, что компакция и resume в Codex 0.164.0 не теряют историю: раньше неудачная компакция оставляла частичные саммари.

Microsoft выпустила TokenEconomizer: плагин, который режет расход токенов агента на 18–31% по итогам прошлых сессий

TokenEconomizer (Microsoft, Apache-2.0, статья arXiv 2610.22732, Berkeley + MSR) — плагин для Claude Code, Codex, Copilot CLI и Pi. Он читает завершённые сессии в репозитории и по ним подстраивает следующие. Три механизма. Микро-скиллы: факты об окружении, которые агент каждый раз открывает заново (например, нет команды pytest, а работает python -m pytest), записываются и сообщаются в начале новой сессии; без вызовов модели. Прунинг инструментов: если инструмент пять сессий подряд не использовался, он убирается через штатные настройки агента (toolprune=propose требует подтверждения, toolprune restore возвращает всё). Защита от циклов: когда ход зацикливается на «правка — падающий тест» намного дольше обычного, шлётся один редирект, затем подсказка, как прервать; сам ход плагин не останавливает.

По SWE-Bench (277 задач, 6 репозиториев) средняя цена задачи ниже на 18,4–30,9% в пяти связках агент+модель: Claude Code с Sonnet 5 — 23,6%, с Opus 4.8 — 30,9%. Pass@1 вырос в четырёх из пяти. Данные лежат в ~/.tokeneconomizer. Ограничения: протестированы только Claude Code 2.1.300–2.1.307; сообщения плагина в Claude Code видны только в Ctrl+O, модель может их перефразировать; запись прунинга ждёт час простоя, чтобы не ломать prompt cache.

У тебя уже есть skill observability и settings-cleanup, но они ручные. Здесь прунинг и «выученные» факты идут автоматически. Первый шаг: клонировать репозиторий, добавить как marketplace по абсолютному пути, поставить плагин, один раз выполнить refresh-catalog, затем /tokeneconomizer:status. Версия Claude Code должна быть из проверенного диапазона.

Что взять себе
  • Поставить плагин на один второстепенный репозиторий и включить toolprune=propose, чтобы вручную смотреть, какие MCP-инструменты он предлагает убрать (codebase-memory, Chrome, RunPod и др.).
  • Через ~/.tokeneconomizer/bin/te microskills (бесплатно, из терминала) посмотреть, какие факты об окружении он выучил, и перенести полезные в CLAUDE.md проектов.
  • Сравнить его правило «пять сессий без использования = убрать инструмент» с порогами в settings-cleanup и при случае взять число.
  • Взять идею loop guard для /loop и routines: один редирект, потом подсказка человеку, без жёсткой остановки (в loop-design).

Vercel Labs выпустили durable-harness: Claude Code, Codex и другие агенты как устойчивые к сбоям workflow-сессии

durable-harness (Vercel Labs, Apache-2.0, версия 0.0.x, API нестабилен) запускает кодинг-агентов (Pi, OpenCode, fx от libfx, Claude Code, Codex) как durable-агентов поверх Workflow SDK World. Каждая сессия — это workflow run: разговор, текущий ход и каждый вызов модели и инструмента пишутся в журнал событий. После сбоя ход продолжается из журнала на другой машине, а небезопасный для повтора вызов инструмента второй раз не выполняется. Команды и файлы, выбранные моделью, исполняются не на машине, которая ведёт сессию, а в виртуальном workspace (virtual()) или в собственном Vercel Sandbox сессии (sandbox()). Claude Code и Codex работают только в Sandbox сессии, не в общей Function. У агентов по умолчанию нет инструментов, их нужно добавлять явно.

Старт для Pi: npm install durable-harness @earendil-works/pi-durable @earendil-works/chord @earendil-works/pi-ai just-bash. Дальше агент в lib/agent.ts, чат-роут chatRoute({ open, agent, authorize }) в app/api/chat/route.ts и обёртка withDurableHarness(nextConfig) из durable-harness/next в next.config.ts. Локально работает локальный World без настройки, на Vercel есть управляемое хранилище и очереди, для self-host — Postgres World.

Для тебя: у тебя уже есть headless claude -p, /schedule и /loop, но если процесс упал, ход не возобновляется из журнала. Здесь это решено на уровне инфраструктуры, но только для Next.js и Vercel Sandbox. Для личного Telegram-бота это тяжело, зато как образец дизайна полезно. Первый шаг: открыть github.com/vercel-labs/durable-harness и посмотреть модуль durable-harness/claude-code.

Что взять себе
  • Журнал событий и правило «небезопасный вызов не повторять» — добавить в loop-design проверку: что будет с долгим агентом, если процесс упадёт посреди хода, и какие шаги нельзя выполнять дважды?
  • Идея «команды модели идут не на машине, которая ведёт сессию, а в отдельном sandbox» — добавить в наш скилл subagents/loop-design пункт про изоляцию для автономных циклов без человека.
  • Идея «агент без инструментов по умолчанию, всё добавляется явно» — проверить кастомные agent-файлы (implementer, test-engineer и др.): у каждого ли список tools минимален?

04Hacker News21.10

Omnara: открытый (Apache 2.0) бэкенд для долгоживущих агентов на любой модели вместо Claude Managed Agents

Omnara — самохостимый API для запуска агентов, аналог Claude Managed Agents и OpenAI Agents API. Лицензия Apache 2.0, около 3.2k звёзд. Модели любые: OpenAI, Anthropic, OpenRouter, Bedrock, LiteLLM, Ollama — лишь бы эндпоинт совместим с OpenAI Responses/Chat Completions или Anthropic Messages. Состояние агента — append-only журнал событий в Postgres; воркеры без состояния делают один шаг цикла и ставят в очередь следующий, упавший шаг откатывается и повторяется. Простаивающий агент ничего не стоит. На машину (macOS/Linux) ставится демон omnarad, он сам подключается наружу, входящие порты и SSH не нужны; у агента может быть несколько машин с переключением при отключении. Есть cron-расписания, интеграции со Slack, Discord, GitHub, права на каждый инструмент (авто / с подтверждением / запрет), skills, memory-хранилища, субагенты, MCP. Для сравнения: у Claude Managed Agents цена токенов плюс $0.08 за активный час сессии. В обсуждении HN (110 очков) усомнились в новизне: журнал и персистентность давно есть в чат-продуктах, а Codex хранил JSONL. Автор отвечает, что это бэкенд вроде «Supabase для агентов», без клиента. Локальные настройки по умолчанию небезопасны.

Для твоего сетапа это не замена Claude Code, а слой для агентов, которые должны жить без твоего терминала: бот в Telegram, ночные задачи, мониторинг. С /schedule, /loop и Workflow пересечение частичное, но Omnara даёт устойчивость к падениям и выбор модели. Первый шаг: поднять локально — git clone https://github.com/omnara-ai/omnara.git, cd omnara, docker compose -f compose.yaml --profile app up -d, открыть http://localhost:8000. Затем npx omnara config --api-url http://localhost:8000/api/v1 --issuer-url http://localhost:8000 и npx omnara login.

Что взять себе
  • Поднять Omnara в Docker Compose и запустить один агент из agent.yaml с machine_name на твоём Mac: проверить, как работает демон omnarad без входящих портов.
  • Подключить его MCP-сервер к Claude Code: claude mcp add --transport http omnara https://app.omnara.com/mcp, затем /mcp для входа. Так можно запускать долгоживущих агентов из сессии.
  • Взять у Omnara модель прав «авто / подтверждение / запрет» на каждый инструмент как образец для хуков PreToolUse: явная трёхуровневая таблица вместо россыпи правил.

05Hacker News22.10

NVIDIA выложила OpenShell: песочницу для агентов с политиками на уровне ядра и подстановкой секретов

OpenShell — Apache 2.0 рантайм от NVIDIA (линия 0.1.x, 18k звёзд), в котором агент работает в изолированной песочнице. Ядро ограничивает файлы и системные вызовы, каждое сетевое соединение проходит проверку политики до выхода наружу. Агент не видит настоящих ключей: OpenShell подставляет их только в запросы к разрешённым эндпоинтам, включая инференс. Любое расширение политики (новый хост с ключом, новый метод API) сначала проходит формальную верификацию и ждёт ревью человека. Компоненты: gateway, supervisor, sandbox; gateway ставится в Kubernetes через Helm (CNI должен применять NetworkPolicy). Нужны Linux, macOS на Apple Silicon или WSL 2 (экспериментально) и Docker, Podman или виртуализация хоста. SDK есть для Python, TypeScript, Go, Rust. Анонимная телеметрия включена по умолчанию, выключается OPENSHELL_TELEMETRY_ENABLED=false.

В обсуждении на HN главный довод против: если у агента есть исходящий канал, данные можно вынести, и полностью это закрывает только изолированная сеть. Упоминали альтернативы: sandbox-runtime от Anthropic, matchlock, iron proxy, Docker sbx.

Для твоего сетапа ценнее всего идея подстановки секретов на границе и сетевой allowlist: сейчас у тебя ключи берутся через скилл secrets, а Claude Code с --dangerously-skip-permissions или в Telegram-боте ходит в сеть без такой границы. Первый шаг: curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh, затем openshell sandbox create --name demo. Потом пройти туториал «Run Your First Agent» (OpenCode на бесплатной модели OpenRouter).

Что взять себе
  • Поставить скилл проекта: npx skills add NVIDIA/OpenShell — он учит агента писать политики и отлаживать gateway; посмотреть, что из этого стоит перенять в наш settings-change.
  • Запускать фоновые и ночные агенты (/schedule, /loop, Telegram-бот) в openshell sandbox с сетевым allowlist вместо голого хоста — попробовать на одном роутине.
  • Перенять схему «ключ подставляется на границе, агент его не видит» в скилл secrets: сейчас секрет попадает в окружение процесса, а там он мог бы жить только в прокси.
  • Добавить в loop-design правило: расширение прав агента (новый хост, новый метод API) всегда ждёт ревью человека, как в политиках OpenShell.

06FastAPI releases22.10

FastAPI 0.160.0: extra="forbid" в моделях параметров теперь режет и поля, объявленные в других параметрах

FastAPI у тебя уже есть, поэтому только то, что поменялось. В релизе 0.160.0 (22 октября 2026) изменили поведение моделей для query, header, cookie и form параметров. Раньше настройка extra у такой модели смотрела только на её собственные поля. Теперь она применяется ко всем присланным полям из того же места запроса (query, headers, cookies, form), в том числе к полям из других моделей, отдельных параметров и зависимостей. Это согласуется с поведением Pydantic. Изменение помечено как breaking (PR #16594, автор @tiangolo).

Результат зависит от extra. При extra="forbid" всё, чего нет в модели, отклоняется, даже если это поле объявлено другим параметром или зависимостью. При extra="allow" такие поля попадут в модель как extras. При extra="ignore" (по умолчанию) они игнорируются. Поэтому самый опасный случай у тебя: модель фильтров с extra="forbid" в query плюс отдельный Query-параметр или зависимость (например, пагинация, api_key в header) в том же эндпоинте. Раньше это работало, после обновления может начать отдавать 422. Примеров кода и инструкции по миграции в релизе нет. Первый шаг: поднять fastapi до 0.160.0 в отдельной ветке и прогнать pytest, а в коде найти grep-ом model_config с extra="forbid" у моделей, используемых через Query(), Header(), Cookie(), Form().

Что взять себе
  • Найти grep-ом модели с extra="forbid" в Query/Header/Cookie/Form и проверить, нет ли на тех же эндпоинтах отдельных параметров или зависимостей из того же места запроса
  • Добавить в pytest тест на эндпоинты с моделями параметров: запрос с полем из соседней зависимости не должен возвращать 422
  • Пока не готов к миграции, закрепить fastapi<0.160.0 в зависимостях и обновляться осознанно

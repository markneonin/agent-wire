Jim Manico выложил skill /threat-model: агент строит модель угроз репозитория со ссылками на файлы и строки

grim-prompter (MIT, 185 звёзд, создан 28.10.2026) — набор промптов и один skill `threat-model` для Claude Code и Codex CLI. Агент читает репозиторий строго read-only, пишет только в `threat-model/` и обязан давать к каждой находке путь к файлу и строке. Чего не видно в коде, записывается как gap, а не додумывается. Внутри 36 архитектур (Web, API, Microservices, RAG, Agentic AI, OT/ICS, блокчейн и др.) в вариантах quick и deep и 29 методов: STRIDE, PASTA, LINDDUN, STPA, MAESTRO, MITRE ATLAS, ATT&CK, CVSS, DREAD и другие. Deep-прогон идёт в шесть стадий (scope, моделирование, анализ угроз, challenge, план обработки, отчёт), каждая читает файл предыдущей. На выходе `SYSTEM_UNDER_REVIEW.md`, `report.md` и JSON-артефакты. Для MCP-серверов и инструментов агента он сопоставляет tools с backend-учётками и правами, неизвестные права помечает как gap. Режим `change main...feature` сравнивает ветку с сохранённым JSON-базлайном. Ограничения: промпты — черновики; сборки, тесты и сеть только с явного разрешения; план проверки не равен пройденному тесту; отчёты могут быть чувствительными, их не стоит коммитить.

У вас уже есть вендорное ревью, `/code-review` и subagents, но отдельного security-слоя с моделью угроз нет. Полезнее всего он для ботов с MCP (Telegram, Google Workspace, RunPod) и для проверки веток. Первый шаг: `git clone https://github.com/jmanico/grim-prompter.git ~/grim-prompter`, затем `ln -s ~/grim-prompter/skills/threat-model ~/.claude/skills/threat-model`, новая сессия и `/threat-model quick agentic` в репозитории бота (имя архитектуры сверьте с `catalog.md`).

Что взять себе
  • Поставить skill `threat-model` симлинком в `~/.claude/skills` и прогнать `/threat-model quick` на репозитории Telegram-бота с MCP-доступами.
  • Взять из их runbook правило «неизвестное — в gap, не в догадку» и ссылки file:line для наших скиллов ревью и исследования.
  • Добавить в `.gitignore` проектов папку `threat-model/`, раз отчёты могут содержать чувствительные детали.
  • Гонять `/threat-model change main...feature` как отдельный шаг перед merge рискованных веток, сохранив JSON-базлайн.

02Simon Willison29.10

Spawn: мультиплеерную игру разрабатывает рой агентов на Fable, выкладка в прод каждый час

Джейкоб Сэнсбери (Jacob Sansbury) описал, как устроена компания Spawn: массовая мультиплеерная игра, где игроки промптами меняют мир, а внутриигровой ИИ Савви помогает собирать игры. По его словам, разработкой почти автономно занимается рой агентов на модели Fable. Расход на токены больше $3 млн в месяц, «в 30 раз больше фонда оплаты труда». Агенты правят живой код и выкатывают в прод каждый час, сами читают ошибки, баг-репорты и метрики. Около 60% задач начинается с продакшен-ошибки, жалобы от Савви, странной записи в логе или запроса на фичу. Савви сама заводит баги, агент сортирует их: реальный баг, wontfix или осознанное решение, требующее человека. Большинство превращается в фикс за час.

Правила: час без релиза считается SEV-0, потому что агент удерживает в контексте лишь несколько часов работы, а частые релизы сохраняют связность. Откат одного сломанного изменения занимает 30 секунд. Мониторы и алерты по логам будят агента-владельца инцидента. Команда специально ломает систему, проверяя пути восстановления. Про модели: Opus 5.5 им не подошёл, а GPT-6 Astra при исправлении замечаний по безопасности отключил фичи, и продукт перестал работать. Саймон Уиллисон сомневается, что подход годится для более ответственного софта.

Для вашей настройки это ориентир по замыканию цикла: ошибка из прода сама запускает агента. Первый шаг: на одном небольшом проекте повесить на алерт или лог-монитор запуск `claude -p` с триажем (баг, wontfix, нужно решение) и откатом по одному изменению.

Что взять себе
  • Триаж-агент на входящие ошибки: классифицирует на баг / wontfix / решение для человека. Добавить такой скилл к алертам в наших скриптах `claude -p --json-schema`?
  • Откат одного изменения вместо всего релиза: каждый фикс агента отдельным коммитом с командой отката за секунды. Завести это правило в CLAUDE.md?
  • Правило против «починки отключением»: GPT-6 Astra выключал фичи ради безопасности. Добавить в brief ревью-агентов запрет отключать функциональность и проверку, что фичи работают?
  • Монитор логов, который будит агента-владельца инцидента, через `/schedule` или хук. Попробовать на одном проекте?

03GitHub30.10

Kensaku: локальный поисковик по файлам и скриншотам с OCR и MCP-доступом для агентов

Kensaku (yjid/kensaku, MIT, Rust + Tauri + Bun) — бесплатный локальный лаунчер для поиска. Ищет по именам файлов (автор заявляет около 1,3 мс на 100k файлов на Linux), по тексту внутри PDF, DOCX, PPTX, XLSX, EPUB, ODT, RTF, кода и логов, включая CJK, и по тексту на картинках через OCR. OCR по умолчанию PP-OCRv6, есть опциональный движок Indra (около 27 МБ, скачивается по запросу) и запасной Tesseract; на Intel Mac только Tesseract. Есть поиск по смыслу, терпимость к опечаткам, даты вроде «last week» и язык запросов (`type:`, `ext:`, `size:`, `content:`, `re:`). Индексация инкрементальная, без облака и телеметрии. Платформы: Windows, macOS, Linux. Сборки не подписаны, автообновление не подключено, больше всего проверено на Windows. README не говорит, какая модель считает эмбеддинги, и не перечисляет MCP-инструменты по именам. Репозиторию неделя (создан 24 октября 2026), 241 звезда.

Для агентов: `kensaku-cli mcp` подключается как MCP-сервер, есть HTTP-режим `kensaku-cli serve` на loopback с bearer-токеном. Доступ по умолчанию только на чтение, `reindex` включается явно. Для тебя это способ дать Claude Code поиск по скриншотам, PDF и офисным документам на диске, чего не умеет codebase-memory, который работает по графу кода. Это молодой проект, поэтому сначала проверь, какие инструменты он отдаёт. Первый шаг: скачай релиз, проиндексируй папку со скриншотами и документами, выполни `kensaku-cli search --json <запрос>`, затем добавь в `mcpServers` запись с командой `kensaku-cli mcp`.

Что взять себе
  • Подключить `kensaku-cli mcp` в `mcpServers` и посмотреть, какие инструменты он отдаёт: поиск по скриншотам, PDF и DOCX на диске сейчас не закрыт ни одним твоим MCP.
  • Использовать `kensaku-cli search --json` в скриптах, которые вызывают `claude -p --json-schema`, как дешёвый локальный поиск по документам перед запуском агента.
  • Оставить доступ только на чтение (по умолчанию) и не включать `reindex`, пока не проверишь поведение сервера. Если нужен HTTP, поднимать только `kensaku-cli serve` на loopback с токеном из Keychain через скилл secrets.

04Pydantic releases29.10

Pydantic 2.14: убрали Python 3.9, добавили 3.15, закрыли две уязвимости

Pydantic 2.14.0 вышел 8 октября 2026. Он выбрасывает поддержку Python 3.9 и добавляет 3.15. Закрыты две уязвимости: GHSA-gj4f-r7mf-jjxh (при валидации Fraction принимались огромные экспоненты) и GHSA-955g-x97g-8mcp (в URL с несколькими хостами префикс валидировался повторно).

Из нового: multiple_of для схем fraction и timedelta, параметр __namespace__ в create_model(), core-схемы ordered-dict и counter. Изменения, которые могут задеть код: NameEmail теперь отвергает переводы строки; multiple_of должен быть положительным; конструкторы enum вызываются в обоих режимах валидации; ser_json_timedelta больше не действует на все datetime-типы при выводе сериализации; model_config больше не мутируется. Остальное — исправления: OverflowError в ByteSize, ошибки ОС в ZoneInfo, исключения в Decimal, JSON Schema для stdlib dataclasses и TypedDict (config, init, kw_only, extra). Авторы пишут, что часть правок считается не ломающей по их политике версий, но перед обновлением их стоит прочитать.

Pydantic у тебя уже в стеке (FastAPI, SQLModel), так что важно именно это. Если принимаешь от клиентов Fraction, составные URL или email с именем, обновление закрывает дыры. Если схемы и OpenAPI генерируются из dataclass или TypedDict, они могут чуть измениться. Первый шаг: поднять pydantic до 2.14.0 в отдельной ветке, прогнать pytest и сравнить openapi.json до и после. Если сервисы ещё на Python 3.9, сначала нужно обновить интерпретатор.

Что взять себе
  • Поднять pydantic до 2.14.0 в ветке и сравнить openapi.json до и после: JSON Schema для dataclass и TypedDict поменялся.
  • Поискать в коде Fraction, multi-host URL и NameEmail на входе API: там закрыты уязвимости, добавить тесты на странные значения.
  • Проверить, какие сервисы и CI-образы ещё на Python 3.9, и запланировать переход на 3.10+ или выше.
  • Найти места с ser_json_timedelta и multiple_of в моделях: поведение у них поменялось.

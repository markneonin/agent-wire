Anthropic перестроила Projects в Claude Code: координатор раздаёт цель параллельным облачным потокам

Анонс на странице датирован 17 сентября 2026, на HN его обсуждают в ноябре. Проект теперь принимает цель, а не только папку с контекстом. У каждого проекта есть координатор, он разбивает цель, раскидывает брифы по новым или существующим потокам-воркерам, проверяет результаты и собирает итог. Каждый поток — облачная сессия Claude Code в своей ветке и копии репозитория; пересечения решаются обычными merge-конфликтами. Потоки сами могут делить работу через subagents, loops и workflows, открывают PR и гоняют тесты. У проекта общая память (причины решений, смены планов) и библиотека файлов и артефактов. Можно выбрать модель и effort для координатора и воркеров, видеть расход по проекту и править частоту check-in. Пример из статьи: убрать v1-эндпоинт в API, web и mobile: поток на репозиторий, затем отчёт, какие PR мягдить первыми. Бета для части Pro/Max без старых проектов, лист ожидания claude.com/form/projects. Локальный запуск обещан «очень скоро». В обсуждении Boris Cherny из Anthropic заявил: накладные расходы координатора менее 10% токенов. Критика: облако без локальных файлов, слабый координатор по умолчанию, один запрос породил семь субагентов и съел лимит Max, мало видимости.

Для тебя это в основном UX поверх того, что уже есть: Workflow, worktree-писатели, task-lead и SendMessage. Нового три вещи: общая память проекта между потоками, мобильное управление и работа без твоего компьютера. Пока всё в облаке, а твоя настройка завязана на локальные хуки и MCP, так что это не замена. Первый шаг: встать в лист ожидания на claude.com/form/projects или открыть claude.ai/projects и прогнать задачу «миграция через несколько репозиториев».

Что взять себе
  • Из примера с v1-эндпоинтом: в скилл feature-build/task-lead для задач на несколько репозиториев добавить финальный отчёт «какие PR мёржить первыми» — добавить?
  • Из жалоб на семь субагентов на простой запрос: добавить в скилл subagents или хук потолок на число параллельных воркеров и оценку расхода до запуска?
  • Лист ожидания claude.com/form/projects: попробовать общую память проекта на одной реальной задаче и сравнить с нашим tasks/<slug>/context.md

Agweb: браузер на WebKit для macOS, которым агенты управляют из shell и не крадут фокус

Agweb — одно окно на системном WebKit (macOS 26+), которым агенты управляют командой `agweb`, похожей на playwright-cli. Автор запускал несколько агентов, и окна Chrome от Playwright отбирали фокус клавиатуры, а headless блокировали сайты. У каждого агента свой workspace (`-w`) со своими вкладками, дашборд на ⌘D показывает все вкладки и последнюю команду каждого агента. Клики и ввод — нативные события macOS. Именованный профиль (`-p work`) хранит логины и может быть общим. Ответ на действие описывает, что изменилось (сеть, строки, диалоги, загрузки, ошибки консоли), поэтому второй snapshot обычно не нужен; есть `snapshot --diff`, `find`, `text` (статья в markdown), `video-start` (запись в MP4). `fill --secret-cmd` вводит пароль из 1Password/Bitwarden CLI, не показывая его агенту; `ask` передаёт вкладку человеку для MFA или капчи. Пять простаивающих страниц: 590 МБ и 0% CPU против 1,6 ГБ у Playwright Chrome. Лимиты: только WebKit, нет CDP, `route` мокает лишь fetch/XHR, часть рекламы на YouTube проходит. В HN ругают отсутствие Linux и общий профиль: logout у одного агента ломает остальных.

У тебя уже есть Claude in Chrome и Playwright-скрипты (Avito). Новое — параллельные агенты без фокуса и без общего окна, с экономией токенов на diff-ответах и скрытыми секретами. Первый шаг: скачать Agweb.dmg из Releases репозитория paul-nameless/agweb, затем в меню Help поставить CLI и skill для Claude Code (или `agweb install-cli` и `agweb install-skill`) и проверить `agweb -w task open <url>` и `agweb -w task snapshot`.

Что взять себе
  • Попробовать agweb вместо Playwright в скриптах Avito: отдельный `-w` workspace на агента, без окон Chrome поверх работы
  • Использовать `fill --secret-cmd` вместо нашего скилла secrets для логинов в браузере: пароль не попадает в транскрипт
  • Взять паттерн «ответ на действие содержит diff изменений» и `ask` (передача вкладки человеку для MFA/капчи) в наши браузерные скиллы
  • Проверить `agweb install-skill` и сравнить его skill с нашим browser-use

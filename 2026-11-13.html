01Claude Code releases12.11

Claude Code 2.1.323: экспериментальный Code Mode (Claude пишет JavaScript для вызова инструментов), engines в плагинах и ужесточение прав Bash

Релиз от 12 ноября, в нём 262 пункта. Главное новое: Code Mode, экспериментальный opt-in, где Claude вместо отдельных вызовов инструментов пишет JavaScript, который эти инструменты вызывает. Включение и отключение для организации описаны на code.claude.com/docs/en/code-mode. Эту страницу я открыть не смог (404), поэтому как именно устроено выполнение, какие есть ограничения и какая переменная или настройка его включает, не знаю.

Остальное: в plugin.json появился engines["claude-code"], плагины вне указанного диапазона версий не ставятся, не обновляются и не грузятся. `claude plugin validate` теперь проверяет типы в TypeScript-модуле хуков плагина (предупреждения, с --strict падает). Добавлены CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1 и heartbeat раз в 30 секунд для долгих хуков в `claude -p`. Лимит сообщений между своими сессиями вырос с ~20 до 100 000. Неизвестный ID модели теперь считается с окном 1M вместо 200K (CLAUDE_CODE_DISABLE_1M_CONTEXT=1 вернёт 200K). Много правок прав Bash: правило `Bash(NODE_ENV*)` теперь спрашивает, deny/ask-правила ловят команды через sudo/env, sandbox в worktree блокирует `git worktree add/move/remove`, при невалидном --settings с ключом sandbox `claude -p` останавливается, а не работает без sandbox. Для тебя: Code Mode ближе всего к твоему Workflow, но это другой механизм (код вызывает инструменты внутри одной сессии). Первый шаг: открыть доку Code Mode, когда страница станет доступна, и проверить свои allow-правила Bash с `*` в значении переменной (теперь есть startup-предупреждение).

Что взять себе
  • Проверить свои allow-правила Bash на `*` в значении переменной и на wildcard вида `Bash(ls*)`: теперь они спрашивают или дают предупреждение при старте
  • Если у вас есть хуки или скрипты на `claude -p` с --settings и sandbox: убедиться, что JSON валиден, иначе запуск теперь остановится
  • В собственных плагинах (plannotator, runpod и т.д.) добавить engines["claude-code"] в plugin.json и прогнать `claude plugin validate --strict`
  • Если `/usage` или шапка шумят от субагентов в Workflow: попробовать CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1, чтобы убрать лишние запросы на сводки

02GitHub13.11

cook: скилл для долгих визуальных сборок, где агент итерирует до совпадения с референсами

Leonxlnx/cook (268 звёзд, создан 31.10.2026, MIT) — скилл для задач, где результат должен совпасть с референс-картинками или видео: 3D-миры на three.js, ролики, игры, UI. Ты даёшь цели, планку и время, агент один раз задаёт все вопросы с дефолтами и дальше работает без тебя, хоть ночь. Цикл: каждый референс становится «шотом» (видео разбирается покадрово), на каждое измерение (композиция, свет, цвет, материалы, детали, движение) ставится числовая планка, например 99.9% для кадров и не ниже 9/10 для видео. Рендерятся кадры в тех же ракурсах, склеиваются рядом с референсом, оценивают их критики с нулевым контекстом, исправляется самое слабое, раунд пишется в cook/ROUNDS.md. Твоя собственная оценка результата калибрует баллы критиков, потому что модели завышают себе оценки. Для демо минимум 8 часов (2 часа — «что-то не так»), есть темп под лимиты подписки. Кадры шлются после каждого раунда без остановки, финальный рендер только после одобрения. Пример: Athenaion — около 45 часов, 55 субагентов (до 12 параллельно), ~45k строк JS, ~11M токенов, 4K на встроенной Radeon 780M.

Параллели с твоим сетапом: Workflow, субагенты, /loop, loop-design и task-context уже закрывают оркестрацию и состояние. Нового тут: паттерн «критики без контекста + калибровка по твоей оценке», сравнение рядом с референсом и жёсткий минимум времени против ранней остановки. Первый шаг: npx skills add Leonxlnx/cook, затем /cook build this ... match the 9 attached references. Для сравнения нужны Node 18+ и ffmpeg: node scripts/side-by-side.mjs --out compare.jpg ref1.png render1.png.

Что взять себе
  • Критики без контекста с калибровкой по твоей оценке: добавить в loop-design правило, что самооценку агента сверяют с твоей эталонной оценкой.
  • Скрипт side-by-side.mjs (референс слева, рендер справа) — подключить к Remotion-пайплайну и скиллу montage для проверки кадров.
  • Минимальное время и журнал раундов cook/ROUNDS.md — взять как защиту от преждевременной остановки в долгих /loop и /schedule задачах.
  • Правило «стоп-гейт только на кадрах»: слать скриншоты после каждого раунда без паузы, финал только после одобрения — добавить в визуальные задачи скилла frontend.

03Hacker News12.11

Google выпустил в Antigravity модель Gemini 4 Hydrogen и режим Orchestrator, который переключает Carbon и Hydrogen внутри одной задачи

Google (блог Antigravity, 12 ноября 2026) раскатывает Gemini 4 Hydrogen: модель для повседневной агентной работы. Индекс Artificial Analysis 51 (у Argon 50, на максимальном уровне 54), Terminal-Bench 4.1 даёт 57% против 18,2% у 3.8 Flash. Четыре уровня reasoning: low, medium, high (по умолчанию) и новый xhigh.

Orchestrator — новый пункт в списке моделей. Он внутри одной задачи переключает Gemini 4 Carbon и Hydrogen: Carbon читает код и планирует (только чтение), Hydrogen правит файлы, обновляет пакеты, гоняет тесты. Если Hydrogen упирается в проблему, задача возвращается к Carbon, и тот чинит план. На Terminal-Bench 4.1 это почти уровень Carbon при в среднем на 24% меньшей квоте и на 19% быстрее. Раньше на неделе вышли Carbon и команда /swarm (параллельные агенты в нескольких worktree). Antigravity SDK позволяет собрать такую связку программно; в демо Hydrogen сортирует issues и пишет код, Carbon делает крупные рефакторинги и проверки безопасности. Доступ: Hydrogen для Google AI Pro и Ultra, Orchestrator (Carbon) только для Ultra, Orchestrator (Argon) для Pro и Ultra. Цен и лимитов в статье нет. В обсуждении HN: планировщик + дешёвый исполнитель уже делают advisor mode у Anthropic и пайплайн GitHub; Antigravity ругают за быстрый расход квоты Pro; один комментатор сообщил о 60% экономии, когда Opus делегирует дешёвым моделям DeepSeek.

Для вас это не новая идея: у вас есть сабагенты с моделью и effort на каждого, task-lead и /swarm-подобный Workflow, плюс скилл use-antigravity для agy -p. Новое только паттерн «сильная модель читает и планирует, дешёвая правит, при сбое возврат к планировщику». Первый шаг: проверить, что агент-исполнитель (medium или low) при провале тестов возвращает задачу ведущему, а не чинит сам.

Что взять себе
  • Добавить в скилл subagents правило эскалации: исполнитель (low/medium) при повторном провале тестов возвращает задачу ведущему на перепланирование, а не чинит вслепую.
  • Разделить права по фазам, как в Orchestrator: агент разведки и планирования только читает, правки и тесты делает отдельный агент. Закрепить в agent-файлах.
  • Замерить в своих Workflow экономию квоты и времени от связки «сильный планировщик + дешёвый исполнитель» против одной сильной модели, как это сделали на Terminal-Bench (-24% квоты, -19% времени).

04GitHub13.11

antiglaude: локальный шлюз, который пускает Claude Code на модели Google Antigravity через ненадёжный обход

antiglaude (168 звёзд, создан 2026-11-03, MIT, PyPI, Python 3.10+) — локальный прокси на 127.0.0.1:8080. Принимает запросы Claude Code (POST /v1/messages, Anthropic Messages API) и OpenAI-совместимых клиентов (/v1/chat/completions), переводит их в вызовы Google Cloud Code/Antigravity и возвращает ответ обратно. Модели: claude-sonnet-4-6 (по умолчанию), claude-opus-4-6-thinking, gemini-3-flash, gemini-2.5-pro; неизвестное имя модели уходит на самую сильную доступную, а в ответе подставляется имя из запроса. Внутри: чистка JSON Schema (propertyNames, anyOf, const), которые дают HTTP 400 на tool calls; автообновление токена (живёт около 60 минут) по refresh-данным, вытащенным из локального состояния приложения; SSE-heartbeat против обрывов; бэкофф по лимитам; TUI с квотой, матрицей моделей и журналом запросов; LaunchAgent на macOS. Минусы по README: нет аутентификации (любой локальный процесс ходит в шлюз), «скруббинг идентичности» для обхода фильтров, подписи моделей в таблице путаные (sonnet-4-6 назван Claude 3.7), лимит 1500 запросов/день виден только в примере дашборда. Автор сам предупреждает: Google банит аккаунты на неофициальных прокси, нужен отдельный одноразовый аккаунт.

Для тебя это в основном любопытство: у тебя Opus 5.5 и Sonnet 5.5 напрямую, плюс agy -p для задач на подписке Google AI Pro официальным путём. Полезны идеи: подмена ANTHROPIC_BASE_URL и CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 для списка моделей в /model, и нормализация схем инструментов под чужой бэкенд. Если пробовать, то только на burner-аккаунте: uvx antiglaude start, затем antiglaude setup-claude (он перезаписывает ~/.claude/settings.json, сначала сделай копию).

Что взять себе
  • Проверить, что ANTHROPIC_BASE_URL + CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1 заполняют /model чужими моделями, и описать это в скилле use-antigravity как возможный путь для шлюза.
  • Если решишь пробовать: сначала скопировать ~/.claude/settings.json, поднять uvx antiglaude start на отдельном аккаунте и проверить командой make status.

05ruff releases12.11

Ruff 0.17.5: новое правило ASYNC401, B008 не трогает frozen dataclass, несколько фиксов автоисправлений

Ruff 0.17.5 вышел 12 ноября 2026. Стабильные изменения: B008 (вызов функции в значении аргумента по умолчанию) теперь игнорирует создание frozen dataclass, что убирает ложные срабатывания; исправлены автофиксы B010 (setattr со скобками), PYI034, UP031 (дублировал закрывающую скобку), ICN001 (затенение имён при замене алиасов импорта), а также фиксы, добавляющие или убирающие keyword-аргумент со значением в скобках. Ruff больше не падает при записи в закрытый stderr-пайп. Ещё 18 PR с ускорениями.

В preview: ASYNC401 (pytest-raises-exception-group), PLE0211 (no-method-argument), RUF202 (renamed-rule), RUF101 расширен на другие suppression-комментарии; автофикс G004 (f-строки в логах) помечен как unsafe; FURB103 не предлагает фикс, если write вложен в выражение. Для твоего стека на FastAPI/Pydantic самое заметное — B008: если в Depends/Field-подобных дефолтах используешь frozen dataclass, предупреждения исчезнут. ASYNC401 полезен для asyncio-тестов с ExceptionGroup под pytest. Первый шаг: обновиться (`pip install -U ruff` или `uv tool upgrade ruff`; установочный скрипт: `curl --proto '=https' --tlsv1.2 -LsSf https://releases.astral.sh/github/ruff/releases/download/0.17.5/ruff-installer.sh | sh`), прогнать `ruff check` и посмотреть, что изменилось по B008. Для превью: `ruff check --preview --select ASYNC401,PLE0211`.

Что взять себе
  • Прогнать `ruff check --preview --select ASYNC401,PLE0211` по asyncio-тестам и классам, чтобы оценить новые правила до включения в конфиг
  • Убрать из pyproject.toml `per-file-ignores`/`noqa` для B008, которые стояли только из-за frozen dataclass в дефолтах, и проверить, что их больше не нужно
  • Если в CI стоит `--fix` с G004, не полагаться на автофикс: теперь он unsafe и требует `--unsafe-fixes`

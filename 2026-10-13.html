Хантли: вместо правки AGENTS.md ставить pre-commit хук, который валит коммит и подсказывает агенту нужную библиотеку

Саймон Уиллисон процитировал пост Джеффри Хантли «nobody should type code by hand anymore. here's what's left.» (ghuntley.com/agency/), 13 октября 2026. Проблема: агент не использует его библиотеку diagnostics и вызывает модули observability напрямую. Можно было бы дописать правило в AGENTS.md, но между текстом правила и реальным поведением остаётся разрыв, и он со временем расходится ещё сильнее.

Вместо этого Хантли пишет pre-commit хук. Хук смотрит git diff и ищет прямые вызовы модулей observability в обход его модуля diagnostics. Если нашёл, коммит падает, а в вывод хука подставляется подсказка для агента: использовать библиотеку. По его словам, после этого агент становится полностью послушным. Принцип: правило, которое можно проверить машинно, лучше держать в проверке, а не в инструкциях.

У тебя хуки Claude Code и CLAUDE.md уже есть, так что сама идея «хук вместо инструкции» знакома. Новое здесь: хук на уровне git (pre-commit), который разбирает именно diff и в сообщении об ошибке сразу говорит агенту, что делать. Первый шаг: выбрать одно правило из CLAUDE.md, которое агент нарушает (например, прямой вызов вместо твоей обёртки), и написать pre-commit со скриптом, который ищет нарушение в `git diff --cached` и печатает, чем заменить.

Что взять себе
  • Взять одно часто нарушаемое правило из CLAUDE.md (прямой вызов в обход нашей обёртки) и превратить в pre-commit хук по `git diff --cached`
  • В сообщении об ошибке хука писать агенту готовую инструкцию, чем заменить вызов, как это делает Хантли
  • Добавить в скилл settings-change правило: если правило проверяется по diff, сначала хук, а текст в CLAUDE.md только запасной вариант

02GitHub13.10

Strands Box: Rust-песочница для агентов с политиками Dogwood и подстановкой секретов вне агента

Strands Box (strands-agents/box, Apache-2.0, Rust, preview, создан 2026-10-02, 393 звезды) запускает любой агентный бинарь в изоляции на уровне ОС и ограничивает файлы, программы и сеть. Настройка в двух файлах: box.toml (окружение и прямые доступы) и policy.dw (правила Dogwood permit/forbid). Всё, что проверяется политикой, запрещено по умолчанию, а forbid перекрывает permit. Правила могут зависеть от аргументов, прошлых действий и времени: чтение файла может запретить последующий HTTP-запрос. Egress-шлюз проверяет соединения и HTTP-запросы по методу и пути, а также вызовы MCP-инструментов по аргументам. Секреты подставляет сам шлюз (API-ключи или AWS SigV4), агент их никогда не видит. Решения пишутся в OTLP JSON (private/telemetry/records.jsonl). Ограничения: только macOS на Apple silicon, Linux «planned»; прямые файловые доступы из box.toml проверяет ОС, отдельных решений Dogwood по ним нет. Полного примера policy.dw и инструкции для Claude Code на странице нет, единственный разбор идёт на Strands CLI.

Для тебя это интересно как альтернатива встроенной песочнице и permissions Claude Code, особенно для бота в Telegram и фоновых агентов, где ключи (Keychain, Vault) лучше держать вне процесса агента. Плюс правила по последовательности действий (прочитал секрет, значит нельзя в сеть), которых в hooks PreToolUse нет. Первый шаг на Mac: curl -fsSL https://raw.githubusercontent.com/strands-agents/box/main/download.sh | sh, затем ./box-core/box --version. Скрипт ставит всё в ./box-core и не трогает PATH. Дальше попробуй завести в box.toml безопасный агент вроде claude -p и посмотреть, что видно в records.jsonl.

Что взять себе
  • Поставить Box (download.sh, ./box-core/box --version) и прогнать в нём headless claude -p из одного из твоих скриптов с default-deny сетью
  • Попробовать подстановку секретов через egress-шлюз вместо выдачи токенов из Keychain/Vault в окружение агента бота
  • Добавить правило в духе Dogwood «после чтения секретного файла запретить HTTP» как идею для PreToolUse-хука
  • Смотреть records.jsonl (OTLP) как журнал отказов, чтобы подбирать минимальные права для фоновых агентов

Репозиторий claude-code-mods: набор плагинов на хуках, которые показывают контекст, кэш, лимиты и субагентов прямо над промптом

hamzafer/claude-code-mods (MIT, 225 звёзд, создан 2026-10-02) — маркетплейс плагинов для Claude Code, построенных на хуках. Они выводят живые строки над промптом. Среди них: context-bar (заполнение контекста цветной полосой), token-weather (от Clear до Compact soon плюс обратный отсчёт prompt-кэша), cache-clock (время до остывания кэша, hit rate, сколько токенов перекэшировано), usage-meter (лимиты 5 часов и 7 дней, сброс, стоимость сессии), agent-radar (`/radar`, строка на каждого работающего субагента), review-watch (строка на каждое ревью, Codex или субагент, и тост с находками), replay-theater (`/replay`, правки последнего хода по одному диффу), next-steps (2–3 вероятных следующих промпта по клавишам 1/2/3). Ещё есть blast-radius: задерживает `rm -r`, force push и миграции, показывает, что будет удалено, и отменяет команду через 60 секунд без ответа. Нужен Claude Code 2.1.287+ (cache-clock — 2.1.251+ и Node). Часть модов требует Chrome, `gh`, Codex CLI или macOS. Раздел «My setup» (merge-gate, rulebook-guard) заточен под автора, а в community-модах советуют сначала читать код.

У тебя уже есть хуки, Codex-ревью и свой observability-скилл, так что новое здесь — готовые UI-строки в духе statusline и охранник деструктивных команд с таймаутом. Полезнее всего cache-clock и blast-radius, а остальное можно смотреть как примеры реализации. Первый шаг: `claude plugin marketplace add hamzafer/claude-code-mods`, затем `claude plugin install cache-clock@claude-code-mods` и `claude plugin install blast-radius@claude-code-mods`. Перезапусти Claude Code и запусти `/cache-clock setup`.

Что взять себе
  • Поставить cache-clock: видеть, когда prompt-кэш остыл и сколько токенов перекэшировалось. Это закрывает вопросы про стоимость сессий, которыми занимается скилл observability.
  • Поставить blast-radius и сравнить с нашими PreToolUse-хуками: он задерживает `rm -r`, force push и миграции, показывает, что будет удалено, и отменяет через 60 с без ответа. Перенять таймаут-отмену?
  • Взять идею review-watch: строка на каждое идущее ревью (Codex или субагент) и тост с находками. Добавить такое в наш vendor-review?
  • Попробовать usage-meter, чтобы видеть лимиты 5 часов и 7 дней и стоимость сессии во время работы Workflow с параллельными субагентами.

Скилл answer-me-with-html: агент пишет короткий Markdown, CLI за ~50 мс собирает из него офлайн-страницу с диаграммами

QingYunA/answer-me-with-html (MIT, 3,3k звёзд, репозиторий создан 2026-10-02) — скилл, который заставляет агента отвечать на сложный вопрос одной HTML-страницей вместо стены текста. Модель пишет только Markdown-черновик с frontmatter и блоками-компонентами (flow, er, sequence, tree, timeline, limits, annot, kv, callout, ask, цитаты кода через src= и lines=, таблицы с ok/no/warn). Бандл-CLI `am` (Node 20+, зависимости marked и dagre уже внутри) делает вёрстку, CSS и SVG. Идея в экономии токенов: по подсчёту автора в 9 ручных страницах 47% токенов уходило на координаты SVG, 15% на CSS, 17% на теги и лишь 21% на текст. Собственный бенчмарк (3 темы × 3 прогона, Sonnet 5.5 в Claude Code): в среднем 612 токенов вывода против 4 893 при ручном HTML, медиана 12 с против 31 с; полная стоимость падает лишь на ~15%. При ошибке в черновике CLI отдаёт строку, компонент и пример исправления. Есть темы blueprint/shadcn/paper, комментарии на панелях, блок `ask` с предвыбранным решением агента и кнопка Reply, собирающая ответы в одно сообщение. Страницы лежат в ~/.answer-me-with-html/pages/. Режим «всегда включён» (по умолчанию выключен) добавляет в конец ответа мини-страницу на 2–4 панели со ссылкой file://. Его включают правилом в CLAUDE.md; в plan mode страницы не создаются.

У тебя уже есть публикация артефактов из Claude Code и plannotator для аннотирования HTML, так что новое здесь — именно приём «модель пишет компактный DSL, а рендер детерминированный» и интерактивный `ask`/Reply. Первый шаг: `/plugin marketplace add QingYunA/answer-me-with-html`, затем `/plugin install answer-me-with-html@answer-me-with-html`, и попросить «Explain the TCP three-way handshake» или разобрать структуру модулей репозитория.

Что взять себе
  • Поставить плагин и прогнать на одном реальном вопросе по коду (карта модулей репозитория) — сравнить с нашим вариантом через артефакты.
  • Включить always-on правило из README в CLAUDE.md одного проекта на неделю и посмотреть, не раздувает ли оно ответы.
  • Перенять приём «модель пишет компактный DSL, рендер детерминированный» для наших отчётов (дайджест, observability): сейчас HTML в page.html генерируется иначе?
  • Взять идею блока `ask` с предвыбранным решением и кнопкой Reply для скилла grilling/council: ответы пачкой одним сообщением.

Плагин для Claude Code показывает картинки и видео прямо в терминале Ghostty

claude-show-your-work — плагин (MIT, 173 звезды, создан 8 октября 2026), который даёт Claude два инструмента: show_image и show_video. Картинки рисуются в терминале Ghostty и не уходят в модель, так что токены не тратятся. Видео декодируется через ffmpeg: до 12 кадров в секунду, ширина окна до 2400 px, максимум 900 кадров. Старые файлы удаляются, когда кэш доходит примерно до 1 ГБ.

Из интересного: Claude гоняет фичу в Playwright, записывает прогон и проигрывает в чате. Рядом список изменений, клик перематывает к моменту, а проверки зеленеют или краснеют по ходу видео. Для багфиксов есть режим compare: старая и новая версии играют рядом синхронно. Параметры: path, compare, title, url, changes [{title, at}], summary [{label, ok, passed, total}], summary не длиннее трёх строк. Можно показать страницу в трёх ширинах (десктоп, планшет, телефон) одним изображением.

Для тебя Playwright и Chrome-автоматизация уже есть, нового тут только показ результата в терминале с синхронным before/after. Требования: macOS, Ghostty (в описании репо ещё упомянут kitty), Claude Code 2.1.287+, ffmpeg. В tmux нужен set -g allow-passthrough on. Плагин сам обновляется только из своего репо и шлёт анонимную телеметрию; отключается через env SHOW_YOUR_WORK_AUTO_UPDATE=0 и SHOW_YOUR_WORK_TELEMETRY=0.

Первый шаг: /plugin marketplace add https://github.com/iamumeransari/claude-show-your-work.git#releases, затем /plugin install show-your-work@iamumeransari.

Что взять себе
  • Поставить плагин и прогнать /show-your-work tour, чтобы оценить синхронный before/after на одном из своих багфиксов.
  • Добавить в скилл testing правило: после Playwright-прогона звать show_video с changes и summary [{label, ok, passed, total}], чтобы результат был виден без открытия файлов.
  • Для фронтенд-скилла: показывать страницу сразу в трёх ширинах (десктоп, планшет, телефон) одной картинкой через show_image вместо отдельных скриншотов.
  • Если плагин ставить не хочется: в env settings.json выставить SHOW_YOUR_WORK_AUTO_UPDATE=0 и SHOW_YOUR_WORK_TELEMETRY=0 до первого запуска.

06PyCoder's Weekly13.10

Python 3.15 вышел 9 октября: lazy import, UTF-8 по умолчанию, сэмплирующий профайлер Tachyon

Выпуск PyCoder's Weekly — подборка ссылок; суть в Python 3.15, он вышел 9 октября 2026. Новое: PEP 810 — `lazy import json` откладывает загрузку модуля до первого использования (только на уровне модуля; глобально — `-X lazy_imports=all` или `PYTHON_LAZY_IMPORTS`). PEP 686 — UTF-8 по умолчанию для I/O без `encoding` (откат: `PYTHONUTF8=0`). PEP 798 — `[*L for L in lists]`. Встроенные `frozendict` (PEP 814) и `sentinel` (PEP 661), `TaskGroup.cancel`, tomllib с TOML 1.1. PEP 799: пакет `profiling` с сэмплером Tachyon для работающего процесса (до 1 000 000 Гц, режимы wall/CPU/GIL/exception, flame graph, pstats); модуль `profile` уберут в 3.17.

Бенчмарк Гринберга: fibo(40) 6,94 с на 3.15 против 7,17 с на 3.14, то есть почти без прироста. JIT быстрее на 20–28%. Free-threading на 4 потоках быстрее обычной сборки в ~4,5 раза (fibo) и 1,74 раза (bubble), но на одном потоке bubble медленнее (0,74x).

Для тебя: asyncio и TaskGroup уже знакомы, новое здесь — `TaskGroup.cancel`, Tachyon и lazy import для быстрого старта воркеров Celery и CLI. Риск — UTF-8: проверь контейнеры с нестандартной локалью. Первый шаг: прогнать тесты на 3.15: `python3.15 -X lazy_imports=all -m pytest`.

Что взять себе
  • Добавить в CI матрицу с Python 3.15 и отдельный прогон с `PYTHONUTF8=0`, чтобы поймать расхождения кодировки в файлах и логах.
  • Попробовать `lazy import` для тяжёлых модулей (pandas, SQLAlchemy-модели) в точках входа Celery-воркеров и CLI и замерить время старта.
  • Подключить Tachyon (`profiling.sampling`) к живому FastAPI- или Celery-процессу вместо cProfile и снять flame graph.
  • Заменить самописные `_MISSING = object()` на встроенный `sentinel`, а неизменяемые словари-конфиги — на `frozendict`.

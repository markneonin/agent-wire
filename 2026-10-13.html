AWS-команда Strands выложила Box — песочницу на Rust для агентов с deny-by-default политиками и подстановкой секретов

Strands Box — open source (Apache 2.0) движок песочницы для агентов на Rust, создан 2 октября. Ограничивает, что агент может запускать, читать, писать и куда ходить по сети. Работает с любым агентом: запускаемый бинарник и прямые права (файлы, программы, сеть) описываются в `box.toml`, а правила в `policy.dw` на языке Dogwood (`permit`/`forbid`, всё непроверенное запрещено, `forbid` перекрывает `permit`). Прямые права на файлы держит сама ОС. Shell, Python-интерпретатор Monty, egress-шлюз и MCP-брокер работают в доверенном процессе вне песочницы и делят общую историю событий: прочитанный файл может привести к отказу в более позднем HTTP-запросе. Шлюз видит метод и путь запроса и сам подставляет API-ключи или подпись AWS SigV4, так что секрет агент не получает. Решения пишутся в OTLP JSON в `private/telemetry/records.jsonl`. Пока preview только для macOS на Apple silicon, Linux в планах.

У тебя уже есть hooks на PreToolUse и skill `secrets`, но это правила внутри самого агента. Здесь изоляция снаружи, на уровне ОС, плюс секреты вообще не попадают в окружение агента. Это полезно для Telegram-бота и `claude -p` в скриптах, которые работают без присмотра. README прямо не подтверждает поддержку Claude Code, хотя в репозитории лежат `.claude` и `CLAUDE.md`. Гайд рассчитан на Bedrock. Чтобы попробовать: `curl -fsSL https://raw.githubusercontent.com/strands-agents/box/main/download.sh | sh`, затем `./box-core/box --version`. Дальше смотри `examples/README.md` и skill `authoring-box-policy` из `.agents/skills`: его можно отдать агенту для написания `policy.dw`.

Geoffrey Huntley: правило для агента лучше держать в pre-commit хуке, а не в AGENTS.md

Simon Willison процитировал Geoffrey Huntley (пост ghuntley.com/agency, подзаголовок «nobody should type code by hand anymore. here's what's left»). Мысль такая: если агент не пользуется твоей библиотекой diagnostics, можно дописать это в AGENTS.md, но между описанием и реальным кодом всё равно остаётся разрыв, и со временем он растёт. Вместо этого Huntley пишет pre-commit hook, который смотрит git diff и ищет прямые вызовы модулей observability в обход его diagnostics-модуля. Если находит, коммит падает, а в ответ агенту подставляется промпт «используй diagnostics library». По его словам, после этого агент попадает в правило «десять из десяти». Сам Simon ничего от себя не добавил, цифр и замеров в цитате нет.

У тебя хуки и CLAUDE.md уже есть, так что сама механика знакома. Новое здесь в приёме: любое повторяющееся «пользуйся нашей обёрткой, а не сырым API» переводить из текстовых инструкций в проверку диффа с отказом и подсказкой агенту. Это дешевле по контексту и не дрейфует. Первый шаг: возьми одно правило, которое агент у тебя нарушает чаще всего, и напиши pre-commit хук, который ищет запрещённый вызов в `git diff --cached` и завершается ненулевым кодом с текстом «используй X». Для поиска по форме вызова подойдёт твой ast-grep. Готовой команды в источнике нет, это моя прикидка.

03GitHub13.10

openqodex: проверка кода перед push — сканеры плюс отдельный ИИ-ревьюер на твоём логине Claude Code или Codex

Это open source (Apache 2.0) инструмент ревью перед push, ему около двух недель (репо создан 2 октября). Сначала запускаются сканеры без моделей (gitleaks, semgrep и другие под изменённые файлы). Находки оставляются только на изменённых строках, фикстуры тестов и отключённые правила отбрасываются. Потом стартует отдельный процесс Claude Code или Codex на твоём логине, без своего аккаунта и API-ключа. По умолчанию ревьюит не тот агент, что писал код. Ревьюер обязан по каждой находке сканера либо подтвердить её, либо отклонить с причиной. Скрипты проверяют, что ответ есть на каждую находку и что ревьюеру показаны все изменённые строки. Результат: report.html, md, json, sarif. Дальше агент спрашивает, чинить всё или выбрать. Нужны Node 22+ и git, только macOS/Linux.

С твоим набором пересечение большое: /code-review, vendor-review и plannotator-review уже дают ревью. Новое здесь три вещи. Первая — детерминированные сканеры с проверкой, что ревьюер ответил на каждую находку. Вторая — push-gate: хук Claude Code перед `git push` плюс git pre-push (его обходит `--no-verify`). Вида блокировки по умолчанию нет, только предупреждение, пока в `.openqodex/config.yaml` не задан `review.block_on_severity`. Третья — MCP-сервер с вопросами `openqodex graph`, похожий на твой codebase-memory. Минусы: ревьюеры только Claude Code и Codex, уязвимости проверяются через сеть (osv.dev), даже с `--offline` изменения уходят в модель ревьюера. Попробовать: `npx openqodex demo`, затем `npx openqodex init` в тестовом репо и `~/.openqodex/bin/openqodex review`.

Набор плагинов для Claude Code на хуках: живые строки над промптом (контекст, лимиты, кэш, ревью), защита от опасных команд и игры

hamzafer/claude-code-mods — репозиторий под MIT с десятком плагинов, которые показывают, что делает Claude Code. Нужен Claude Code 2.1.287+. Главное: context-bar (контекст стопкой), token-weather и cache-clock (заполнение контекста и обратный отсчёт prompt-кэша, hit rate, промахи), usage-meter (лимиты на 5 часов и 7 дней, время до сброса, стоимость сессии), agent-radar (одна строка на каждого работающего субагента, /radar), review-watch (строка на каждое ревью, Codex или субагент, и список находок в конце), mission-control (карта агентов, вызовов и файлов, /mission; вид кода требует macOS, Chrome и терминал с картинками), replay-theater (/replay, пошаговый просмотр правок последнего хода), md-preview (рендер Markdown до/после). Из защит: blast-radius останавливает rm -r, force push и миграции, показывает, что будет удалено, и отменяет команду через 60 секунд без ответа. Есть ещё switchboard (выбор модели для субагентов без явной модели, /route) и merge-gate (не даёт gh pr merge, пока CI не зелёный и Codex не посмотрел). Но merge-gate, rulebook-guard и glance заточены под правила автора, их предлагают форкать. Ещё есть игры, Spotify и сторонние моды (subagent-tuner, cache-meter, usage-limits). README прямо советует читать код чужих модов перед установкой.

У тебя уже есть хуки, субагенты с привязкой модели, /code-review и кросс-вендорное ревью, так что логику ты можешь писать сам. Новое для тебя — готовая наблюдаемость: лимиты плана и кэш-таймер, пока ты гоняешь Workflow с параллельными субагентами, и agent-radar с review-watch, чтобы видеть, кто сейчас работает. blast-radius полезен, если у тебя нет своего PreToolUse-хука на rm -r и force push, а если есть, посмотри, как они сделали таймаут на 60 секунд. Первый шаг: claude plugin marketplace add hamzafer/claude-code-mods, затем claude plugin install usage-meter@claude-code-mods и agent-radar@claude-code-mods, потом перезапуск Claude Code. Без установки можно проверить так: claude --plugin-dir mods/context-bar из клона репозитория.

Pensieve: локальный семантический индекс файлов, репозиториев и сессий агентов, который agent вызывает через MCP вместо grep

Pensieve — бесплатное MIT-приложение (только Apple Silicon, macOS 14+; на Linux и Intel Mac работает бэкенд). Оно локально индексирует документы, git-репозитории (с незакоммиченными правками и worktrees), сессии Claude Code, Codex и Qwen Code, Obsidian. Поиск по смыслу или по точным словам, фильтры kind:code, ext:pdf, in:. Агенту отдаётся через MCP (pensieve mcp) вместе с инструкцией «search before you grep», skills и двумя hooks для Claude Code. По замерам автора на Claude Sonnet в Claude Code (72 задачи, 4 репо, до 34 847 файлов): нужный файл найден в 131 из 144 запусков против 123 с grep, 2,0 вызова инструментов против 3,4, $0,041 против $0,050, 8,6 с против 10,9 с. На странице цифры в разных местах не совпадают, а бенчмарк авторский.

В обсуждении на HN скептичны: ripgrep по 11 ГБ кода отвечает за ~0,2 с и не устаревает, индексы отстают после смены веток, у автора slopdex выигрыш был около 10% токенов. Один пользователь пожаловался на кучу Python-процессов, установка через curl | sh тоже вызвала вопросы. Полезное: векторный поиск находит дубли хелперов, которые генерируют LLM, а важны и число round trips, а не только токены. У тебя уже есть codebase-memory (граф кода) и ast-grep, так что для кода это частично перекрывается. Новое — поиск по сессиям агентов, заметкам и файлам вне репо. Первый шаг: curl -fsSL https://tedhaley.ca/pensieve/install.sh | sh, затем pensieve integrate recommended и pensieve setup; удалить можно через pensieve integrate all --remove. Сначала включи только одно репо.

Саймон Уиллисон выпустил web-edit 0.1a0 — веб-редактор файлов в папке, чтобы не гонять секреты через LLM

Это маленькое Python-приложение: веб-интерфейс для просмотра и правки файлов в одной папке. Саймон делал проект с телефона через Codex Remote и захотел поправить файл с credentials так, чтобы секреты не проходили через модель. Приложение написали Codex и GPT-6 Astra Extra High (релиз 12 октября 2026). Редактор — CodeMirror 6 (Monaco выбросили из-за слабого мобильного UX), только UTF-8 текст. Есть список файлов с размером и датой, загрузка нескольких файлов с прогрессом, создание и удаление (с подтверждением), превью картинок до 2 МБ, предупреждение о несохранённых правках и проверка внешних изменений. Аутентификации нет вообще: по умолчанию слушает 127.0.0.1:9000, предполагается запуск по Tailscale. Флаги: -p/--port, -h/--host, -a/--allowed-host (защита от DNS rebinding; при 0.0.0.0 нужно явно перечислить допустимые адреса).

Для тебя это не про Claude Code, а про гигиену секретов: у тебя уже есть skill secrets (Keychain/Vault по алиасу), но когда надо руками поправить .env или токен-файл на сервере или из Telegram-сессии, это способ сделать это без промежуточного агента. Минус — нет авторизации, так что только localhost или Tailscale, и релиз пока альфа. Первый шаг: uvx web-edit ~/sites/mysite (или uvx web-edit --help); для доступа с телефона добавь -h <tailscale-адрес>.

Вышла CLI-утилита bigarrow для macOS: агент рисует поверх экрана стрелку с подписью, а Claude Code и Codex получают для неё готовый skill

bigarrow (репозиторий franzenzenhofer/big-arrow-on-the-screen, создан 8 октября 2026, MIT, около 700 звёзд) — один Swift-бинарник для macOS без демона, иконки в menu bar, аккаунта и телеметрии. Он рисует поверх окон стрелку, рамку или кольцо с подписью. Клики проходят сквозь рисунок, фокус клавиатуры не уходит, а сам рисунок исчезает по таймеру (`--duration`, по умолчанию 8 с для `point` и 300 с для `start`), по `bigarrow stop`, при выходе процесса агента или по клику человека. Цель задаётся по-разному: `--at X,Y`, `--rect`, `--window App:title`, либо `--element "Allow" --app "System Settings"` через Accessibility. Есть `--follow`, `--until-click`, `--say`, `--png`, `--json`, `--dry-run`. Утилита только показывает: не кликает, не печатает и не снимает экран. Ограничения: для `--element` нужен Accessibility, а для `--window` ещё и Screen Recording. Права выдаются приложению, из которого запущен бинарник (терминалу, например), и при их отсутствии выход с кодом 4. В веб-страницах Chrome `--element` работает только с `--force-renderer-accessibility` или VoiceOver, иначе указывать координатами.

Для тебя это закрывает одну дыру: когда агент просит «нажми Allow в System Settings» или «вставь PIN вот сюда», он может показать место на экране. Это полезно в Telegram-боте и при выдаче прав, где у тебя только текст. С Chrome MCP это почти не пересекается: там агент действует сам, а здесь указывает тебе. Skill идёт в формате Agent Skills и в `agents/openai.yaml` для Codex. По README, описание занимает около 182 токенов, а полный текст около 1528. Для автоочистки есть хук `bigarrow stop --hook` на `UserPromptSubmit`: он убирает стрелки сессии, когда ты пишешь следующее сообщение. Первый шаг: `brew install franzenzenhofer/tap/bigarrow && bigarrow install-skill`, потом `bigarrow doctor` для проверки прав и `bigarrow point --at 760,500 --text "Click HERE"` для пробы.

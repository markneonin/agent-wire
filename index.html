Команда Strands выложила Box — Rust-песочницу для агентов с deny-by-default политиками и подстановкой секретов

Box (strands-agents/box, Apache 2.0, превью, создан 2 октября) — движок-песочница на Rust. Агент — любой бинарник, доступ к файлам и программам задаётся в box.toml, а правила пишутся в policy.dw на языке Dogwood: permit и forbid, всё непроверенное запрещено, forbid перебивает permit. Правила могут зависеть от операции, аргументов, прошлых действий и времени: например, если агент прочитал файл, следующий HTTP-запрос блокируется. Egress-шлюз сам подписывает разрешённые запросы (API-ключ или AWS SigV4), так что агент секретов не видит. Решения пишутся в OTLP JSON (records.jsonl). Ограничения: только macOS на Apple silicon (15+), Linux в планах; прямые файловые гранты из box.toml Dogwood не проверяет, а политики по операциям работают только для встроенных Strands Shell, Monty (Python), шлюза и MCP-брокера. Внешние программы и локальные MCP-серверы ходят в сеть только через шлюз. Как именно изолирует ОС, README не говорит (в топиках есть seatbelt).

Для твоего сетапа это интересно как альтернатива жёстким hooks PreToolUse для headless-запусков `claude -p`, бота в Telegram и фоновых агентов: изоляция на уровне ОС, а токены (Telegram, Workspace, RunPod) не лежат в окружении агента. Но README не упоминает Claude Code, а готовый гайд сделан под Strands CLI и Opus 5 на Bedrock, так что совместимость придётся проверять самому. Первый шаг: `curl -fsSL https://raw.githubusercontent.com/strands-agents/box/main/download.sh | sh`, затем `./box-core/box --version` и чтение docs/user/getting-started.md и docs/user/policy.md.

02Simon Willison13.10

Хантли: вместо правки AGENTS.md ставит pre-commit хук, который валит коммит и подсказывает агенту нужную библиотеку

Джеффри Хантли (цитата у Саймона Уиллисона от 13 октября 2026, первоисточник — ghuntley.com/agency) описывает приём. Агент не пользуется его diagnostics-библиотекой и ходит в observability-модули напрямую. Можно было бы дописать это в AGENTS.md, но тогда остаётся разрыв между текстом и реальным поведением, и со временем он расходится. Поэтому Хантли пишет pre-commit хук: тот смотрит git diff и ищет прямые вызовы observability-модулей в обход diagnostics-модуля. Если находит, коммит падает, а в вывод попадает подсказка агенту использовать diagnostics-библиотеку. По его словам, поведение агента после этого сильно улучшается.

У тебя хуки и CLAUDE.md уже есть, так что сама механика знакома. Новое здесь — принцип: правило, которое важно, выносить из инструкций в проверку с обратной связью. Агент получает отказ и сразу текст, что делать вместо этого, и сам исправляет diff. Первый шаг: возьми одно правило из CLAUDE.md, которое агенты нарушают чаще всего (например, обход общего враппера или запрещённый прямой вызов). Напиши pre-commit скрипт, который ищет нарушение в `git diff --cached`, завершается с ненулевым кодом и печатает в stderr короткое указание, чем заменить вызов. Затем убери или сократи это правило в CLAUDE.md. Готовых команд в источнике нет, это только идея.

03GitHub13.10

openqodex: локальное ревью перед git push — 22 сканера плюс отдельный Claude Code или Codex как ревьюер

Это CLI на Node 22+ (macOS/Linux), который проверяет непушнутые коммиты и незакоммиченные правки. Сначала запускаются 22 встроенных сканера (секреты, безопасность кода, уязвимости зависимостей, линтеры, GitHub Actions, Dockerfile/Terraform/k8s, SQL-миграции), и остаются только находки на изменённых строках. Затем отдельный процесс Claude Code или Codex на твоём логине (ключ и аккаунт не нужны) должен по каждой находке либо подтвердить её, либо отклонить с причиной. Скрипты проверяют, что ответили на все находки и что ревьюеру показали все изменённые строки. По умолчанию код не ревьюит тот агент, который его написал. На размеченных багах recall у Claude Code 84,3%, у Codex 75,2%, у одних сканеров 62,7%. Отчёт идёт в report.html/md/json/sarif. Проект до 1.0, конфиг и команды могут меняться. Apache 2.0, телеметрии нет, но изменения уходят в модель за твоим логином.

С твоим /code-review и vendor-review это пересекается, но новое тут вот что: детерминированные сканеры перед моделью, проверка полноты ответов ревьюера и git pre-push hook, который по умолчанию только предупреждает. Блокировать пуш можно через review.block_on_severity в .openqodex/config.yaml, а `git push --no-verify` обходит хук. Мелочи: ruby, go и cargo-сканеры требуют своих рантаймов, а сканер Bearer под Elastic License 2.0. Попробовать: `npx -y openqodex@0.12.0 init --yes --agent claude-code`, затем `~/.openqodex/bin/openqodex review` в репозитории с правками.

Набор плагинов для Claude Code: строки над промптом с контекстом, лимитами и ревью, плюс защита от rm -r и force push

Репозиторий hamzafer/claude-code-mods (создан 2 октября 2026, 225 звёзд) — маркетплейс плагинов на хуках, которые рисуют живые строки над промптом. Ставятся по одному. Нужен Claude Code 2.1.287+. Состав: context-bar (контекст одной полосой по категориям), token-weather и cache-clock (заполнение контекста и обратный отсчёт prompt cache), usage-meter (лимиты 5 часов и 7 дней, стоимость сессии), agent-radar (по строке на каждого запущенного субагента), review-watch (строка на каждое ревью через Codex или субагента, модель, время, последний вывод, в конце список находок), mission-control (карта агентов и файлов, `/mission`), replay-theater (`/replay` — пошаговый просмотр правок последнего хода), md-preview. Из защитного: blast-radius останавливает `rm -r`, force push и миграции и показывает, что будет удалено; без ответа отменяет через 60 секунд. Есть и развлечения (snake, Spotify, Shorts) и личные плагины автора под его правила (merge-gate держит `gh pr merge` до зелёного CI и одного ревью Codex).

С тем, что у тебя уже есть, пересекаются хуки, subagents и Codex-ревью. Нового здесь — готовая видимость: сколько осталось контекста и кэша, кто из субагентов что делает, на каком этапе ревью, при длинных Workflow и фоновых агентах это полезнее всего. Для этого есть и subagent-tuner из community-списка: модель и effort для каждого субагента. У тебя они уже заданы в agent-файлах, так что он тебе вряд ли нужен. Важно: плагины чужие, код стоит просмотреть перед установкой. Как именно хуки рисуют строки, в README не сказано, смотри docs/mods.md. Первый шаг:

claude plugin marketplace add hamzafer/claude-code-mods claude plugin install agent-radar@claude-code-mods

Затем перезапусти Claude Code. Для проверки без установки: `claude --plugin-dir mods/context-bar` из клона репозитория.

Саймон Виллисон выпустил web-edit 0.1a0 — веб-редактор файлов, чтобы править секреты с телефона мимо LLM

Simon Willison собрал (вместе с Codex) маленькое Python-приложение web-edit, версия 0.1a0. Поводом стало то, что он работал с телефона через Codex Remote и ему понадобилось поправить файл с credentials так, чтобы секреты не проходили через саму модель. Приложение показывает папку (имя, размер, дата), даёт скачать, удалить (с подтверждением) и загрузить файлы с прогрессом и своими путями, а текстовые UTF-8 файлы правит в CodeMirror 6, который нормально работает на мобильном. Картинки до 2 МБ показываются inline. Сохранение явное, есть предупреждение о несохранённых правках и проверка внешних изменений. Аутентификации нет: по README запускать только в доверенной сети или через Tailscale. По умолчанию слушает 127.0.0.1:9000, защита от DNS rebinding пропускает только свой адрес и localhost.

Для твоей схемы это закрывает конкретную дыру: Telegram-сессия с Claude Code на телефоне, где токен или .env приходится либо диктовать агенту, либо ждать ноутбука. Здесь агент только поднимает сервер, а значение ты вводишь сам, и оно не попадает в контекст. Это дополняет твой skill secrets (Keychain/Vault), а не заменяет: тот выдаёт секрет команде, этот даёт руками править файл. Сам не пробовал, альфа и без авторизации, поэтому не вешай на 0.0.0.0 без -a. Первый шаг: `uvx web-edit ~/путь/к/папке -h <tailscale-ip> -p 9000`, затем открыть адрес с телефона.

Sphinx: git-хук, который перед push задаёт вопрос по диффу кода от агента

Sphinx — бесплатный open-source (MIT) git-хук. Когда ты или агент делает push в защищённую ветку, git ставится на паузу, а ревьюер-модель читает дифф (чат с агентом она не видела) и спрашивает, что изменение делает в сбойных сценариях. Пример с сайта: обработчик вебхука сохраняет ID события до вызова `charge()`, вопрос — что будет при ретрае. Неверный ответ даёт объяснение и новый сценарий, верный пропускает push. Ставится так: `npm install -g sphinx-understand` (нужен Node 22.19+, macOS, Linux или WSL), затем `sphinx install` — подключает git и агентов (Codex, Claude Code, Cursor, OpenCode, Pi) и спрашивает, какая модель ревьюит: текущий агент, OpenRouter или любой OpenAI-совместимый endpoint. `sphinx yolo` отключает вопросы, каждый пропуск логируется. Ответы агенту не передаются, `.env` и ключи не читаются. Критерии оценки ответов на странице не описаны. В обсуждении на HN (246 очков) скептики говорят, что вопросы можно скопировать в агента, тест с вариантами провоцирует угадывание, а мусор в диффе (отладочный код, ослабленные assert, выдуманные импорты) квиз не ловит. Предлагали гейтить PR, а не прод-push, и проверять умение найти неверные допущения. Из альтернатив: PR-описание с разделением why/what/how и скилл «quiz me on the PR».

У тебя уже есть ревью-слои (`/code-review`, vendor-review, quality-reviewer), но все они проверяют код, а не твоё понимание. Sphinx закрывает именно это: хук заставляет тебя разобраться в diff, прежде чем он уйдёт. Первый шаг: `npm install -g sphinx-understand && sphinx install` в одном небоевом репозитории и выбрать ревьюером Claude Code.

Что взять себе
  • Поставить Sphinx на один репозиторий и посмотреть, насколько вопросы по диффу полезнее твоих ревью-скиллов, которые проверяют только код.
  • Сделать свой скилл «quiz me on the PR» для больших агентских PR: вопросы о сбойных сценариях (ретрай, частичный отказ) по диффу, который ты не писал сам.
  • Добавить в шаблон PR/коммит-скилла блок why/what/how, как советовали в обсуждении: он вытаскивает скрытые решения LLM.

DeepSeek выпустил V4.1-Flash-1017: 763B, 1M контекста, MIT, Terminal-Bench 4.0 вырос с 31.2 до 42.3

DeepSeek-V4.1-Flash-1017 — «минорное обновление» V4.1-Flash. Веса открыты под MIT, 763B параметров (BF16/F32/F8/I8), контекст 1M токенов, рекомендуемый max_tokens — 256K+, sampling temperature 1.0 и top_p 1.0. Заявлены рост в рассуждении, коде, агентных задачах и зрении, а также более короткий вывод и меньшее время выполнения, то есть дешевле задача. По таблице карточки: Terminal-Bench 4.0 (харнесс Claude Code) 42.3 против 31.2 у прошлой версии; DeepSWE v1.1 77.0 (Opus 5 — 74.0, GPT-5.6 Sol — 73.0); ProgramBench 29.1; NL2Repo 68.2; Automation-Bench 60.5. Но на Terminal-Bench Opus 5 даёт 51.8, на HLE 56.3 против 42.6, на NL2Repo 75.3 — по большинству строк Opus 5 впереди. Цену карточка не называет. Запуск: vLLM, SGLang (OpenAI-совместимый API), Docker Model Runner, 64 квантизации для llama.cpp/Ollama/LM Studio. Есть deepseek-recipe: Rust-библиотеки с Python-биндингами, которые переводят запросы Messages, Chat Completions и Responses в промпт модели и разбирают tool calls и thinking; Jinja-шаблона нет.

В обсуждении на HN (944 очка) хвалят скорость, низкую цену и «человеческий» код без излишней хитрости; один портировал игры на Rust примерно за 3 евро. Минусы: у собственного API DeepSeek, по слухам, логируются и используются для обучения входные данные (у сторонних хостов есть zero-data retention), есть жалобы на галлюцинации, на локальном Q3_XS модель зацикливается, а Q4_K_S стабилен. Для тебя это не замена Opus 5.5, а дешёвый кандидат на роль исполнителя или второго мнения рядом с Codex, Gemini и opencode. Первый шаг: подключить модель через OpenRouter или Fireworks в opencode и прогнать на одной задаче из бэклога, сравнив с Sonnet 5.5 по времени и стоимости.

Что взять себе
  • Добавить DeepSeek V4.1-Flash-1017 в скилл vendor-review как ещё одного рецензента через провайдера с zero-data retention (Fireworks) — по цене почти бесплатное второе мнение?
  • Прогнать одну и ту же задачу из бэклога на Sonnet 5.5 и на DeepSeek через opencode, замерить время, длину вывода и стоимость — завести заметку в observability?
  • Не слать приватные репозитории и секреты в собственный API DeepSeek: добавить в скилл secrets/vendor-review правило использовать только провайдеров с zero-data retention?

DeepSeek запустил API поиска и загрузки страниц: $0.75 за 1000 успешных запросов

DeepSeek открыл два сырых JSON-эндпоинта с Bearer-ключом: POST https://api.deepseek.com/v1/tools/search (собственный поисковик) и POST .../v1/tools/fetch (страница в Markdown). Поиск: query до 128 символов, count 1–50, need_content для полного текста, ori_question для понимания запроса. Операторы: site:, -site:, "фраза", lang:, after:, before:. В ответе у каждого результата rerank_score 0–3 (≥1.5 — хорошо), summary на 600–800 символов, date, authority 0–4.

Цена $0.75 за 1000 успешных запросов и для search, и для fetch. Платно только при HTTP 200 с непустым результатом; пустые ответы, ошибки и таймауты бесплатны. Лимиты: search 100 QPS, fetch 25 QPS плюс лимит на домен. При использовании через DeepSeek Harness, Claude Code или Codex серверные вызовы сейчас бесплатны, платные с 1 ноября 2026 (00:00 по Пекину). Страница не описывает связку с function calling и список моделей. В обсуждении на HN сравнивают цены: Brave $5, Exa ~$4, Serper ~$1, Ceramic $0.25 за 1000. Качество, по отзывам, лучше у Exa и Tavily. Главное возражение: API DeepSeek не с нулевым хранением данных, поэтому запросы с чувствительным содержимым туда отправлять рискованно.

Для тебя это дешёвый запасной поиск и fetch для своих скриптов и headless-агентов, где встроенный WebSearch дорог или недоступен. Первый шаг: curl https://api.deepseek.com/v1/tools/search -H "Authorization: Bearer $DEEPSEEK_API_KEY" -H "Content-Type: application/json" -d '{"query":"claude code hooks after:2026","count":5}'. Ключ хранить через скилл secrets.

Что взять себе
  • Сделать скилл или MCP-обёртку над /v1/tools/search и /v1/tools/fetch с ключом из skill secrets, как дешёвый запасной поиск для claude -p скриптов.
  • Фильтровать результаты по rerank_score ≥ 1.5 и authority ≥ 3, а full-текст брать только через need_content или fetch для отобранных URL: так меньше токенов в контексте.
  • Добавить в CLAUDE.md правило: в DeepSeek search не отправлять приватные запросы (данные, имена, внутренний код), так как нулевого хранения данных нет.

FastAPI 0.146.0: параметр root_path в FastAPI() объявлен устаревшим

В релизе FastAPI 0.146.0 (18 октября) параметр root_path в конструкторе FastAPI() помечен как deprecated. В заметках он идёт в разделе Breaking Changes (PR #16520, автор @tiangolo). Вместо этого предлагается задавать корневой путь при запуске сервера: fastapi run --root-path /api/v1. Больше в заметках ничего нет: ни причины, ни срока удаления параметра, ни примеров миграции.

Это важно, если приложение стоит за прокси или API-шлюзом с префиксом, например /api/v1, и в коде есть FastAPI(root_path="/api/v1"). После обновления такой код начнёт выдавать предупреждение о deprecation, а позже параметр, вероятно, уберут (срок в релизе не указан). Если у вас предупреждения в pytest превращены в ошибки (filterwarnings = error), CI может упасть сразу. Первый шаг: выполнить grep -rn "root_path" по сервисам, найти FastAPI(root_path=...), перенести значение в команду запуска (fastapi run --root-path /api/v1) или в Dockerfile/манифест, затем проверить, что /docs и openapi.json по-прежнему отдаются с правильным префиксом. Если сервис запускается напрямую через uvicorn, а не через fastapi run, как там задавать префикс, в заметках не сказано, это надо смотреть в документации.

Что взять себе
  • Прогнать grep по всем FastAPI-сервисам на FastAPI(root_path=...) и составить список, что переносить в команду запуска
  • Заменить параметр в Dockerfile/compose/k8s-манифестах на fastapi run --root-path /api/v1 и проверить /docs за прокси
  • Проверить, не превращает ли конфиг pytest предупреждения в ошибки, прежде чем поднимать FastAPI до 0.146.0

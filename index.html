Плагин effortless сам выбирает reasoning effort на каждый промпт и показывает остаток prompt cache

effortless (MIT, HeyCubit) — плагин для Claude Code на хуках. Перед каждым промптом «судья» (по умолчанию Haiku 5.5 на твоём логине, опционально Jev от TypeSafe по API-ключу, Haiku — запасной) ставит effort: простой вопрос — Low, тяжёлая задача — High. Короткие «ок/да» effort не меняют. Ручная смена effort выключает Auto. Работает только на Opus 5.5 и Sonnet 5.5; на Fable 5.1 и старых моделях Auto на паузе. Над промптом — полоса: effort, модель, заполненность контекста в % и таймер до остывания prompt cache. Когда кэш остыл и чат большой, предлагает Compact или Handoff (Quick — быстрая сводка, Full — ещё смотрит git и пишет HANDOFF.md). Сводки пишет Haiku 5.5, при сбое — обычный compact. Предупреждает, когда лимиты выше 80%, и включает Save mode с потолком Medium.

Цифры автора (прогон 2026-10-10, 4 задачи × 3 запуска, все 12 верны): на Opus 5.5 $0.149 за задачу против $0.190 на medium, $0.209 на high, $0.257 на xhigh (−21/−29/−42%). Точность судьи на 73 размеченных кейсах: Haiku ~92–93%, Jev 99%, «всегда medium» 44%. Оговорки автора: выборка мала и задачи лёгкие, на сложных экономия меньше, тесты шли на свежих API-чатах, а не на длинных сессиях подписки; Haiku ошибается на «да/спасибо» после тяжёлой работы.

Для тебя это ближе всего к ручной привязке effort в агентах (high/xhigh), но на уровне основной сессии, плюс видимость кэша и контекста, чего у тебя нет. Попробовать: `/plugin marketplace add HeyCubit/effortless`, затем `/plugin install effortless@effortless`, `/reload-plugins`, `/effortless setup`. В терминале может понадобиться `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`. Ключ Jev из мастера настройки лежит в `~/.config/jev/.env` открытым текстом.

Что взять себе
  • Поставить effortless на одну неделю и сравнить расход с обычным ручным effort — у нас нет авто-выбора effort для основной сессии.
  • Взять идею таймера prompt cache: хук/статусную строку, которая показывает, сколько осталось до остывания кэша, и предупреждает перед возвратом в большой чат.
  • Добавить в наш handoff-процесс вариант Full: сводка + проверка git + запись HANDOFF.md, а сводку делать через Haiku 5.5, как в плагине.
  • Скопировать правило Save mode: при лимитах выше 80% ограничивать effort уровнем Medium.

Разработчик игр описал, как сделать игру «обвязкой» для агента: сид, odiff по скриншотам, команды, samply

Кайл Кукштель (пост от 10.10.2026, по мотивам доклада в Калгари 12.09.2026) утверждает: LLM плохо справляются с играми, потому что значительная часть игры — не код (ассеты, сцены, баланс), а агенту нужна среда, где он может действовать, наблюдать и проверять себя. Его набор приёмов: один сид для всей случайности, чтобы любое состояние воспроизводилось; встроенный скриншот движка и переключатели слоёв UI; odiff (CLI) выдаёт diff-картинку и число сходства (пример «85% similar») — после кропа это количественная метрика на каждый ход вместо шумного сравнения «до/после» глазами модели; сохранение/загрузка точного состояния с первого дня; один тип Thing на всё; каждое изменение состояния как сериализуемая команда (можно воспроизвести баг и «рулить» запущенной игрой без компиляции); статические числа вне кода; симуляция отдельной библиотекой без движка; samply сбрасывает профили в текст, и агент сам крутит цикл «замер — правка».

Целый цикл (правка, симуляция, diff скриншота, профиль) по его словам занимает секунды за один ход агента. В HN-обсуждении добавляют: headless-запуск для параллельных тестов, бот-игроки для баланса, чексуммы состояния между платформами в CI, экспорт метрик как временных рядов. Критика: модели ломают код при мелких правках, «Thing» не потянет производительность без ECS, а «ощущение» игры словами не описать.

Для твоего сетапа игры вторичны, но принцип переносится на Remotion-пайплайн и ботов: дать агенту числовую проверку результата. Первый шаг: поставить odiff и прогнать им кадр из bot/video/ до и после правки Gfx.tsx.

Что взять себе
  • Числовая проверка кадров: odiff до/после правки графики в Remotion-пайплайне (bot/video) — добавить в скилл montage шаг со сравнением и порогом сходства?
  • Сид и воспроизводимость: зафиксировать единый seed в генерации видео/графики, чтобы агент мог перезапустить ровно то же состояние при отладке — добавить в тесты montage?
  • Профили как текст: для медленных скриптов (montage.py) снимать профиль в текстовом виде и отдавать агенту на цикл «замер — правка» — завести такой скилл?

03GitHub14.10

VibeStart: CLI собирает TypeScript-проект под AI-агентов с AGENTS.md и проверенными комбинациями стека

VibeStart (MIT, 151 звезды, репозиторий создан 2026-10-04) - CLI и веб-студия, которые собирают full-stack TypeScript-проект из выбранных слоёв. Слои: React SPA (TanStack Router), TanStack Start или Next.js; Electron и Expo; бэкенд Hono или встроенный; API oRPC/OpenAPI; PostgreSQL, MySQL, SQLite, MongoDB; Drizzle, Prisma, Mongoose; Better Auth; Docker; shadcn + Tailwind 4; Vitest, Playwright или TesterArmy; Vite+, Oxlint, Knip. Результат - обычный репозиторий без рантайм-зависимости от VibeStart.

Для агентов внутри лежит AGENTS.md (куда и как вносить изменения) и единая команда `vp run ready`: типы, lint и тесты, самые быстрые первыми. CLI отказывается от невозможных комбинаций и называет минимальную правку. Перед релизом каждую поддерживаемую комбинацию и каждую тройку выборов ставят, проверяют типы, lint, тесты, браузерные тесты и сборку в CI; результаты с отпечатками лежат в ветке `verification`. Команда `upgrade` делает трёхстороннее сравнение шаблона, вашего проекта и нового шаблона и показывает превью, не трогая прикладной код. CLAUDE.md и хуки в README не упомянуты.

Для твоего сетапа: скиллы, хуки и субагенты у тебя уже есть, новое здесь - готовый стартовый шаблон с быстрым единым gate для агента. Полезно, когда нужно быстро поднять новый TS-проект, в котором агент сразу получает обратную связь за секунды. Первый шаг: `npx vibestart-cli my-app --list`, затем `--dry-run`; или `npx skills add VinkyDev/vibestart --skill vibestart`.

Что взять себе
  • Перенять идею одной команды `vp run ready` (типы, lint, тесты, быстрые первыми) как обязательный gate в CLAUDE.md и Stop-хуке для TS-проектов?
  • Попробовать `npx vibestart-cli my-app --dry-run` и сравнить сгенерированный AGENTS.md с нашими CLAUDE.md - что стоит забрать?
  • Добавить в скилл feature-build правило: отказ от невозможных комбинаций с причиной и минимальной правкой, как в CLI?

Вышел llm-gemini 0.35 с поддержкой Gemini 4 Argon: $2/$10 за миллион токенов, с 1 декабря цена вырастет вдвое

Саймон Уиллисон выпустил llm-gemini 0.35: плагин для CLI `llm` теперь умеет работать с новой моделью Gemini 4 Argon. Модель доступна 13 октября 2026 через Gemini API и для подписчиков тарифа Google за $100 в месяц. Сейчас Argon стоит $2 за миллион входных и $10 за миллион выходных токенов: как GPT-6 Sol и вдвое дешевле Claude Opus 5.5. С 1 декабря цена удвоится и сравняется с Opus 5.5.

Уиллисон подчёркивает, что цена за токен мало говорит о стоимости. Важнее, сколько токенов модель тратит на задачу в агентной обвязке. Artificial Analysis оценил прогон своего бенчмарка на Argon в $2 407. Это близко к GLM-5.3 и заметно ниже последних моделей OpenAI, Anthropic и Meta. Даже после повышения цены Argon, по его ожиданию, останется чуть дешевле GPT-6 Astra. Пеликаны на велосипеде (SVG) на уровнях low, medium и high получились отличными, high обошёлся в 17,166 цента. Страница не перечисляет опции плагина и не описывает, как модель ведёт себя в агентных задачах, так что про кодинг по ней судить нельзя.

Для вас это повод проверить Argon как второго рецензента рядом с Gemini CLI, пока действует цена $2/$10. Первый шаг: `llm install -U llm-gemini`, затем `llm models`, чтобы найти идентификатор Argon. Точное имя в посте не приведено, его надо смотреть в списке.

Что взять себе
  • Добавить Argon в скилл vendor-review как ещё одного рецензента через `llm`, пока цена $2/$10 до 1 декабря.
  • Мерить стоимость по токенам на задачу, а не по цене за токен: в observability-скилле сравнить расход Argon и Opus 5.5 на одном и том же ревью.

Каталог dev-quality-gates: по одному проверенному инструменту на задачу, с промптом для агента

mokevnin/dev-quality-gates (159 звёзд, создан 23.10.2026, CC0) — не awesome-list, а выборочный список: на каждую задачу один инструмент, с записанными ограничениями, датой проверки и источниками в tools.json. Критерии: инструмент обязан завершаться с ненулевым кодом при нарушении, работать без интерактива, давать машиночитаемый вывод и безопасный autofix. Предпочтение быстрым Rust-тулам (Ruff, Oxlint/oxfmt, Mago, rumdl). Там, где нет проверенного выбора, категория остаётся пустой (раздел under review: Trivy после компрометации в марте 2026, Brakeman из-за лицензии, Semgrep/Opengrep). Куски: Knip, dependency-cruiser, ty, deptry, import-linter, golangci-lint, cargo-deny, squawk (миграции Postgres), oasdiff (breaking changes API), diff-cover (покрытие изменённых строк), Betterleaks (секреты), OSV-Scanner, lychee, typos, mise для версий, hk (~170 готовых шагов git-хуков), commitlint. Из Claude Code-специфичного — agnix: линтит CLAUDE.md, AGENTS.md, SKILL.md, хуки и MCP-конфиги, exit 1 на ошибках, на предупреждениях с --strict.

Главное для агентной разработки: docs/adopt.md — инструкция для агента. Из корня репозитория просишь агента прочитать её, выбрать подходящее, показать план до правок, подключить проверки в хуки и CI и убедиться, что каждая проверка реально может упасть. Для тебя ast-grep уже есть (он тоже в списке как инструмент своих правил). Новое: agnix для аудита твоих многочисленных скиллов и хуков, diff-cover и docs/patterns.md. Первый шаг: поставить agnix и прогнать по ~/.claude и проектным CLAUDE.md, а docs/adopt.md скормить агенту в одном проекте.

Что взять себе
  • Прогнать agnix по ~/.claude и проектным CLAUDE.md/SKILL.md/хукам: ловить ошибки конфигов скиллов и MCP (exit 1, --strict для предупреждений) — добавить в settings-cleanup?
  • Добавить diff-cover в тестовый скилл и Stop-хук: падать, если изменённые строки не покрыты тестами
  • Взять правило из adopt.md «проверка должна уметь упасть» в скилл process/feature-build: агент доказывает, что новый гейт краснеет на заведомо плохом коде
  • Попробовать hk (hk.pkl) вместе с mise для параллельных git-хуков и закреплённых версий инструментов вместо ручных хуков

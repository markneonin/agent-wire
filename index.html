rsrc: CLI, через который агент читает X, Reddit, YouTube и другие площадки, плохо видимые веб-поиску

rsrc отдаёт по каждой команде один JSON: текст, автор, дата, вовлечённость. Источники: X (посты, треды, ответы, ленты, поиск), Reddit, Hacker News, YouTube (с транскриптами), публичные посты LinkedIn с комментариями, App Store с отзывами. Только чтение, без API-ключей, MIT. Выдача каждой площадки свежая, без общего ранжирования и кэша. Коды выхода: 0 — есть результаты, 66 — пусто, 2 — ошибка аргументов или настройки, 1 — сбой (rate_limited, blocked, not_found). Автор заявляет: на X и Reddit в 2–12 раз быстрее Agent-Reach, в 264 прогонах ни одного ложного успеха, в тесте на пяти темах минимум по 4 URL на тему, пропущенных веб-поиском. Это раннее ПО одного автора, на живых источниках проверено только на macOS. Маршруты неофициальные и могут сломаться. X, Reddit и LinkedIn ограничивают автоматический доступ, аккаунт могут лимитировать.

Тебе это даёт одну команду для этих площадок, дополняющую веб-поиск, помимо Claude in Chrome. Поиску в X нужна твоя сессия: Ego Lite, куки auth_token и ct0 в ~/.config/rsrc/x.env (права 600 или строже) либо экспериментальный rsrc x connect через Chrome. Поиску и живым тредам Reddit нужен Ego Lite; без него reddit read берёт публичный архив Arctic Shift. Начни без логина (Python 3.11+, uv): uv tool install git+https://github.com/SamuelZ12/research-sources, затем rsrc check hn appstore.

Что взять себе
  • Подключить скилл rsrc (npx skills add SamuelZ12/research-sources) и вызывать его из твоего deep-research в паре с веб-поиском?
  • Добавить транскрипты YouTube через rsrc youtube read в ресёрч? Нужны yt-dlp и deno: brew install yt-dlp deno.
  • Перенять в своих скриптах для агентов контракт rsrc: отдельный код 66 для пустой выдачи и именованные ошибки при сбое, чтобы сбой не сошёл за «ничего не найдено»?
  • Если подключать X, записать в скилл правило: мало запросов, а порядок поиска с x-graphql после сбоя может перейти на твой аккаунт?

02GitHub28.11

Clipy: открытый рекордер экрана, который превращает видео в текстовый файл со скриншотами для ИИ-агентов

Clipy (Apache-2.0, репозиторий от 22 ноября, 274 звезды) записывает экран и голос. Людям достаётся ссылка, агенту — `recording.arec`: Markdown с расшифровкой, кликами, ключевыми моментами, таймкодами и скриншотами (формат AREC 1.4). Моменты выбирают локальные правила по выделениям, рисункам, кликам и паузам курсора. Опциональная модель ловит реплики вроде «вот тут ломается», ffmpeg снимает по кадру на момент. Речь распознаётся локально (Apple speech на macOS, иначе Parakeet или Whisper), для YouTube и Loom есть их субтитры. Десктоп только для macOS и Windows, на Linux лишь CLI.

Whisper у тебя уже есть. Новое — готовый путь «видео → контекст агента»: `/watch` принимает YouTube, Loom или локальный файл вместе с вопросом. На macOS агент может и сам записывать выбранное окно и ставить метки. Нужно запущенное приложение, первая запись требует твоего согласия. С Ollama или LM Studio и локальной расшифровкой всё остаётся на машине. Облачная модель получает текст, подписи кликов и ограниченную выборку событий мыши и клавиатуры, но не видео и скриншоты. Облачная расшифровка отправляет аудио провайдеру. Первый шаг в Claude Code: `/plugin marketplace add clipy-recorder/clipy`, `/plugin install watch@clipy`, затем `/watch ./demo.mov summarize this`.

Что взять себе
  • Поставить плагин `watch@clipy`, чтобы агент разбирал видео по запросу вроде «list every bug the speaker points out» по ссылке Loom или локальному файлу?
  • Попробовать отдавать агенту баги записью с голосом: `clipy record --local --max 120`, а потом путь к `recording.arec`, который напечатает команда?
  • Добавить в скилл проверки UI на macOS запись прогона: `clipy session start --local --source mac-screen`, `clipy mark "..."` на каждом шаге, `clipy session stop --local`?
  • Для приватных экранов закрепить в настройке Clipy локальную расшифровку и `CLIPY_MODEL_PROVIDER=ollama` с `CLIPY_MODEL`, чтобы данные не уходили облачным провайдерам?

03GitHub28.11

PopAgent: локальный веб-интерфейс для pi, Codex, Claude Code, OpenCode и DSH, где ход агента можно поправить на лету

PopAgent (MIT) показывает в диалоге рассуждения агента, вызовы инструментов, изменённые файлы, токены и стоимость. Базы данных нет: сессии остаются файлами самого движка. Поправка на лету нативная только у pi (движок по умолчанию). У Claude Code, Codex, OpenCode и DSH это «stop-and-resend»: ход останавливается, и поправка отправляется заново. Claude Code подключён по ACP через `claude-code-acp`: сессии общие с CLI `claude`, инструменты подтверждаются по каждому вызову, есть выбор модели, но нет уровней reasoning и сабагентов. Панель сабагентов только у pi. Также есть задачи по cron с таймзоной, голос, граф плана, Web Push и PWA, управление приложениями macOS.

Твой Claude Code тут получит веб-окно и доступ с телефона, но с урезанными возможностями; работу твоих скиллов и хуков в этом режиме прочитанный текст не описывает. Интереснее это как общий интерфейс для нескольких движков. По умолчанию слушает только 127.0.0.1; для удалённого доступа нужны `-H 0.0.0.0` и пароль, заданный на самой машине, а 3 неудачных входа блокируют на 30 минут. Первый шаг: при Node ≥ 22.19 выполни `npm -g install pop-agent`, затем `pop-agent`. Есть и `.dmg` для Apple Silicon, но с ad-hoc подписью, поэтому Gatekeeper может не пустить первый запуск.

Что взять себе
  • В PopAgent запуски по расписанию не пишут в файлы, пока это явно не разрешено в задаче: сделать такое правило для твоих `claude -p` и cron-агентов в skill loop-design?
  • Там ход, превысивший лимит watchdog, прерывается и записывается как неудачный: проверить, что так же ведут себя твои фоновые и headless-запуски?

v2: версии для видеопроектов, которые делают с кодинг-агентами, включая футаж и рендеры

v2 (лицензия MIT) хранит версии видеопроекта, над которым работают Claude Code, Codex или другой агент. Код и текст идут в git, а футаж, музыка и рендеры в собственное хранилище v2. По README, любая версия восстанавливается в точности. `v2 init` настраивает проект и учит агента сохранять версию после каждой правки вместе с промптом, который её вызвал. `v2 log` показывает версии. `v2 diff` открывает их в браузере: можно посмотреть одну, сравнить две и оставить для агента комментарии с таймкодами. `v2 restore 3` возвращает версию 3 как новую. `v2 push` загружает проект на v2.video и выдаёт приватную ссылку. Нужны git и ffmpeg, установщик рассчитан на macOS и Linux. README не объясняет, как устроено хранилище, что меняет `init`, как комментарии доходят до агента, кто может открыть ссылку и есть ли лимиты.

Git у тебя есть, новое для твоих Remotion и `montage` здесь другое: общая история кода и медиа, привязанная к промптам, и визуальное сравнение версий. Первый шаг: `curl -fsSL https://v2.video/install.sh | sh`, затем `v2 init`. Скрипт стоит сначала прочитать, а `init` запустить на копии проекта и посмотреть, что изменилось. `v2 push` отправляет проект на внешний сервис, для локальной пробы он не нужен. Релизы подписаны, `v2 update` проверяет подпись перед заменой. Для сборки из исходников нужны Go и Node 24, `go install` не работает.

Что взять себе
  • В v2 каждая версия хранится с промптом, который её вызвал. Добавить в скилл `montage` сохранение версии после каждой правки через v2?
  • `v2 diff` сравнивает две версии в браузере и принимает комментарии с таймкодами. Попробовать это как этап ревью роликов из `montage` и Remotion, заодно проверив, как комментарии доходят до агента?

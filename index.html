vvv: готовые Remotion-шаблоны видео и скилл, который заполняет их фото и текстом

vvv (Vibe Vision Video, v0.1, MIT, 293 звезды, 4 коммита, создан 22.10.2026) — набор редактируемых Remotion-шаблонов плюс Agent Skill. Идея: сцены, раскладка, тайминги и проверки рендера делаются один раз, а для нового ролика меняются только фото, имена и даты, текст, музыка и формат. Вы описываете фильм одной фразой, агент выбирает шаблон, расставляет фото, пишет текст, рендерит пробник, прогоняет проверки и отдаёт ролик вместе с редактируемым проектом. Есть режим recreate: пересобрать референсное видео из ваших материалов. Шаблонов шесть: Doodle, Album (и вертикальный Album 9:16), DV Story, Comedy, Starter; форматы 16:9 и 9:16. CLI: `vvv.py describe` показывает слоты фото, поля текста и настройки, `validate` ловит плохие входные данные до рендера, `vvv check` меряет формат, звук, кадры и попадание в бит, но часть результата всё равно оценивает человек. Видео и голос не генерируются. Бенчмарка экономии токенов нет, это только заявление авторов. Проверено на Claude Code и Codex, macOS ARM64. Нужны Python 3.9+, Node.js 26, npm.

У вас уже есть Remotion-пайплайн, montage и ElevenLabs, так что ценность не в самом Remotion, а в схеме: шаблон с описанным контрактом (слоты, поля) и валидацией, которую агент вызывает до дорогого рендера. Первый шаг: `/plugin install vvv --marketplace actionow-ai/vvv`, затем попросить ролик одной фразой и посмотреть вывод `describe` и `validate`.

Что взять себе
  • Взять паттерн describe/validate: у наших Remotion-шаблонов вывести список слотов и полей и проверять входные данные дешёвой командой до рендера — добавить в скилл видеопайплайна?
  • Добавить в пайплайн автоматический `check` после рендера (формат, звук, попадание в бит) и отдавать человеку только спорное — сделать?
  • Поставить `/plugin install vvv --marketplace actionow-ai/vvv` и сравнить его шаблоны и режим recreate с нашим пайплайном на одном ролике.

motion2code: скилл, который по видео пишет зацикленную SVG+GSAP-анимацию и сверяет её с оригиналом покадрово

Репозиторий lovisdotio/motion2code (192 звезды, создан 20 октября 2026, MIT) — набор скиллов для кодинг-агентов. Автор исходит из того, что агент «анимирует вслепую»: не видит видео, угадывает тайминги, easing, цвета и текст, а луп прыгает. Поэтому процесс жёстко разбит на шаги. study_video.py берёт кадр каждые 0.25 с, кадры вокруг каждого hard cut, contact sheet, плоскую палитру и оценку лупа (всё в study.json). Агент пишет страницу по контракту window.anim = { tl, duration, seek(t), play(from), pause() }, где seek(t) — чистая функция времени, а последний момент возвращается к первому кадру. frame_diff.py кладёт оригинал и код рядом, считает разницу по времени и выводит пять худших моментов. check_anim.py проверяет контракт, allowlist скриптов, отсутствие растра и видео; с --runtime запускает страницу headless и проверяет ошибки консоли, сетевые запросы, шов лупа, детерминизм seek и автоплей. render_anim.py рендерит точные кадры в MP4/GIF/PNG. Для записи экрана сайта собирает рабочий сайт на GSAP ScrollTrigger. Примеры: 6 клипов по 10–15 с, 24–60 КБ каждый; пересобраны Claude Opus 5.5. Порогов pass/fail и формулы метрики разницы в README нет. Нужны Python 3.9+, ffmpeg, Playwright.

Своё ревью, скиллы, Remotion и frontend-роутер у тебя уже есть, новое здесь — сам приём: заставить агента «видеть» результат через детерминированный seek(t) и покадровое сравнение. Это применимо к твоему Remotion-пайплайну и анимационным задачам. Первый шаг: claude plugin marketplace add lovisdotio/motion2code, затем claude plugin install motion2code@motion2code, и прогнать на коротком ролике.

Что взять себе
  • Контракт seek(t) как чистая функция времени: добавить в frontend-скилл правило для анимаций, чтобы любой кадр можно было отрендерить и сравнить с референсом.
  • frame_diff.py выводит пять худших моментов по разнице с оригиналом: взять этот приём в проверку визуальных задач (скриншоты до/после) в скилле process.
  • check_anim.py --runtime ловит ошибки консоли, сетевые запросы и недетерминизм при headless-запуске: оформить как Stop-хук для HTML-артефактов.
  • Поставить плагин motion2code и сравнить с нашим Remotion-пайплайном на одном коротком ролике.

Moonshot выпустила Kimi K3.1 Pro и Highspeed: открытая модель 3T с контекстом 1M, веса до 4 ноября

Moonshot выпустила Kimi K3.1 Pro — дообученную версию K3 с заметно большим объёмом post-training, 3T-класс, контекст 1 млн токенов, открытые веса обещаны до 4 ноября 2026 (лицензия не названа). Highspeed — вариант в 2–3 раза быстрее (цифр tokens/s нет). В API: kimi-k3.1-pro и kimi-k3.1-pro-highspeed, есть Zero Data Retention. Цены в блоге нет; в обсуждении HN называют $2 вход / $10 выход за млн токенов. Бенчмарки по их данным: Terminal-Bench 4.0 — 65.7% (Opus 5.5 — 66.4%, GPT-6 Astra — 58.2%); BenchCAD с инструментами 92.7% (Opus 5.5 — 96.2%); доля галлюцинаций на их Hallu Bench Hard 8.3% против 23.4% у K3 (Opus 5.5 — 15.0%). Часть замеров делали в Claude-Code harness. Из данных об обучении для открытых весов убрали киберданные, поэтому кибер-способности слабее закрытых моделей (xdev-bench-hard 81.0% против 33.3% у K3).

В HN (854 очка) главная жалоба — лимиты подписок: у некоторых одна задача съедала 5-часовой лимит; ещё пишут про многословные рассуждения, из-за которых цена за задачу выше цены за токен. Бенчмаркам верят не все; одни хвалят модель как планировщика при дешёвом исполнителе, другие — «слишком многословна». Для тебя это не замена Opus 5.5 в Claude Code: страница не говорит, что модель работает внутри него. Это дешёвый второй мнений-кандидат, когда выйдут веса. Первый шаг: в Kimi Code выполнить /model и выбрать Kimi K3.1 Pro, либо взять kimi-k3.1-pro в API и прогнать на одной своей задаче.

Что взять себе
  • Прогнать kimi-k3.1-pro на одной реальной задаче и сравнить стоимость за задачу (а не за токен) с Sonnet 5.5 — в HN жалуются на многословность.
  • Добавить Kimi K3.1 Pro кандидатом в скилл vendor-review как ещё одного рецензента, если дадут доступ через API.
  • Когда выйдут веса (до 4 ноября), проверить, помещается ли что-то из семейства на MLX локально, и узнать лицензию.

Antirion: open-source LLM-шлюз на Rust с роутингом, бюджетами и логом каждого запроса

Antirion (eliasbiondo/antirion, Apache-2.0, репозиторий создан 17 октября 2026, 180 звёзд) - self-hosted шлюз между приложениями и провайдерами: OpenAI, Anthropic, Gemini, Bedrock, Azure OpenAI, Vertex AI, Mistral, vLLM. Один Rust-бинарник со встроенной консолью. Умеет роутинг (fallback-цепочки, веса, least-cost/least-latency, ретраи, hedging, circuit breaker), бюджеты и лимиты в долларах или токенах на уровне организации, команды, проекта и ключа (soft/hard/с подтверждением), guardrails на PII, секреты, регэкспы, JSON-схемы и права на инструменты, точный и семантический кэш, MCP- и A2A-шлюзы, Prometheus и OTLP. Журнал запросов хранит маршрут, попытки, токены, стоимость и вердикты guardrails.

Заявленный оверхед: медиана 0,53 мс при 5000 RPS на 4 vCPU (Bifrost 2.2.4 - 19,7 мс, LiteLLM 1.103.1 при такой нагрузке - 100% ошибок). Это замеры самих авторов, harness лежит в bench/. Нативные бинарники только под Linux, на macOS - контейнер или сборка из исходников.

Для тебя это единая точка учёта расходов на Claude/Codex/Gemini и скрипты с claude -p: виртуальные ключи с бюджетами на каждый пайплайн или ночной агент, fallback между провайдерами. README не упоминает Claude Code и ANTHROPIC_BASE_URL, совместимость нужно проверять; Anthropic SDK направляется на http://localhost:8080. Первый шаг: docker run -p 8080:8080 -p 8081:8081 -v antirion-data:/var/lib/antirion eliasbiondo/antirion, взять admin token из первого запуска и открыть http://localhost:8081/ui/.

Что взять себе
  • Поднять Antirion в Docker и прогнать через него один скрипт с claude -p, выставив base URL на http://localhost:8080 с виртуальным ключом - проверить, работает ли это с Claude Code.
  • Завести отдельный виртуальный ключ с жёстким дневным бюджетом для ночных агентов и /loop-рутин, чтобы они не выжигали деньги без присмотра.
  • Использовать журнал запросов (токены, стоимость, кэш) как источник данных для скилла observability вместо ручной прикидки, куда уходят токены.

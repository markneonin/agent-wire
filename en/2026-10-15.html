agentplay: a local viewer that replays Claude Code, Codex and other agent sessions as a map and a timeline

agentplay (Entelligence-AI, Apache-2.0, repo created 14 October 2026, 151 stars) reads local agent session logs (~/.claude, ~/.codex, ~/.cursor) and opens two views in the browser at http://127.0.0.1:7317/. The map is a radial tree of repos, files, shell verbs, MCP servers, subagents, errors, models and outputs such as commits and PRs. The timeline plays back at 1x/4x/16x with scrubbing and lanes for prompts, errors, edits, tokens, cost and compactions. The keys E/X/D/O/R jump to edits, errors, delays, outputs and retries; there is an Errors tab and scoping by task, model or subagent. Supported: Claude Code (highest fidelity, subagent lanes), Codex, Cursor, Copilot CLI, Copilot in VS Code, OpenCode, Kiro; the others show only the main lane. Python 3.11+, no dependencies. Per the README, data never leaves the machine, there is no telemetry, and the map excludes prompt text, file contents and command arguments (shell is stored as the verb only). Limits: cost is an estimate from public list prices, sessions are capped at 20,000 events, transcripts over 512 MB are skipped, and Write can't always tell create from overwrite.

You already have the observability skill and Workflow with nested leads, but that is analysis, not a visual replay. What is new is seeing where a multi-agent run had retries, errors and delays, which MCP servers were actually called, and how cost grew before compactions. First step: run `uvx agentplay` (or `pipx run agentplay`), then `agentplay list --agents claude --since` with your period, and open a session that used Workflow or several subagents.

Take for your setup
  • Run `uvx agentplay` on your latest Workflow/subagent session to find retries and delays, and feed what you find into the observability skill as a source?
  • Use the Errors tab and the MCP nodes on the map to check which MCP servers (codebase-memory, Telegram, Chrome) are actually called, and drop unused ones from always-loaded config during settings-cleanup?
  • Use the tokens, cost and compaction lanes to find where the Telegram bot session bloats, and tune the CLAUDE.md rules accordingly?

OpenCode 2.0 ships: always-on local service, Code Mode for MCP, background subagents and hot-reloading plugins

OpenCode 2.0 is a major update to the open-source coding agent. The server now always runs as a single background process on your machine, and the TUI, web and desktop apps all connect to it; other hosts can connect via /pair or opencode pair. The API was rebuilt from scratch and the agent can call it on itself (worktree_create, session_move, session_prompt, session_interrupt and so on). New packages: @opencode/client and @opencode/sdk (the same code as the CLI, embeddable in your own server).

The key new piece is Code Mode (@opencode/codemode): a minimal JavaScript interpreter turns MCP servers and OpenAPI endpoints into functions, so the model writes one script (call a tool, map over results, call another) instead of a chain of separate tool calls. All MCP servers are opted in by default, and the author says you can add a thousand with minimal context bloat. Also: background subagents (including on a different model), background shell commands, and Ctrl+B to push a slow command or subagent to the background. 80+ internal plugins, everything hot-reloads, so the agent can write a plugin for itself mid-session. Downsides: 1.0 plugins break and the server API is different. From the HN thread: plugin tools reportedly ignore permission settings, sandboxing needs --standalone, and users report high RAM and stuck sessions.

You already have Workflow, background agents, hooks, MCP and claude -p; what's new is Code Mode and the persistent local service with its API. First step: on a test machine update to the latest 1.x, run opencode upgrade --major, connect a couple of MCP servers and see how Code Mode cuts the number of tool calls.

Take for your setup
  • Code Mode: for multi-step MCP chains (Google Workspace, Telegram) try the pattern of one script instead of a series of calls, and test in opencode whether such a layer is worth it for our MCP servers
  • In the cross-vendor review skill, run opencode 2.0 with --standalone as a sandbox, given reports that plugin tools bypass permission settings
  • Try opencode api / @opencode/client for scheduled runs as an alternative to claude -p in scripts and compare ergonomics

03Claude Code releases14.10

Claude Code 2.1.300: mod hooks, cache-write tokens in OTel, strict updatedInput validation

Release 2.1.300 (14 Oct 2026) is mostly fixes, but a few items matter if you build on top of Claude Code. For mods: the `agent.spawn` hook can now rewrite `prompt` and `model` of Workflow agents (before it could only refuse them), there is a new `prompt.change` hook (fires when the prompt text changes without typing: history recall, clear, undo, a plugin's fill), `virtualText` in prompt decorations, and `$.ui.view({ agentId })` to show an agent's transcript in the main view. In OpenTelemetry the `api_request` event gains `cache_creation_5m_tokens` and `cache_creation_1h_tokens` (cache writes split by lifetime), and trace spans get GenAI attributes: `gen_ai.provider.name`, `gen_ai.conversation.id`, `gen_ai.tool.name`, `error.type`.

Behaviour changes: `updatedInput` from PreToolUse and PermissionRequest hooks is now validated like the tool's own input — unknown keys are dropped, and input the tool rejects denies the call. Agent hooks now honor their `model` (aliases like `haiku` resolve, an unavailable model falls back to the caller's). SessionEnd hooks run more reliably when you exit with a background command, and those commands are force-killed 1.5 s after the stop request. Background sessions resume a carried workflow through the Workflow tool's approval. Fixed: `ENABLE_TOOL_SEARCH=auto` switching off mid-conversation, `--worktree` starting from the wrong commit, subagents vanishing from `/tasks`. Local transcripts now record each request's system prompt, tools and parameters. `CLAUDE_CODE_GZIP_REQUEST_BODIES=0` disables the new gzip on large requests.

For your setup: you have many PreToolUse hooks and use worktrees, so check that your `updatedInput` carries no extra keys — such a call may now be denied. First step: update Claude Code and rerun the hooks that modify tool input.

Take for your setup
  • Run every PreToolUse/PermissionRequest hook that returns `updatedInput` and strip extra keys — unknown keys are now dropped and input the tool rejects denies the call.
  • Surface `cache_creation_5m_tokens` and `cache_creation_1h_tokens` in the observability skill to see how much goes into cache writes by lifetime.
  • If you use mods with Workflow: try the `agent.spawn` hook to rewrite `model` and `prompt` of workflow agents, e.g. a cheaper model for small steps.

cheap-ag: an MCP server where Opus plans, a cheap model codes in a worktree, and only test-passing work is delivered

cheap-ag (npm `cheap-agent`, MIT, TypeScript) is an MCP server and Claude Code plugin. Opus writes a short task; a cheap model (via OpenCode Go, OpenRouter, DeepSeek or Command Code) works in a separate git worktree and must write a test that fails before its fix and passes after. The server runs the tests itself instead of trusting the model's report. Passing work lands uncommitted; it never commits or pushes. If the cheap model can't finish a step, Sonnet takes over (`takeover: "sonnet"`) or Opus itself (`"self"`, capped at 15 tool calls). The per-step turn limit is `limits.max_turns`, default 25.

Benchmarks on SWE-bench Verified with Opus 5.5: one feature 154k vs 57k Opus tokens (−63%), 7 everyday bugs 1.6M vs 655k (−59%, 7/7 both), 9 hardest 3.0M vs 1.3M (−55%, 6/9 alone vs 7/9 with a Sonnet helper). The author admits little gain on tiny tasks, and that having Opus review every green result cost 3x the tokens and caught nothing. The "50x" in the note is not measured; the stated goal is a $20 plan acting like $50–70.

For your setup it overlaps with worktree-per-writer plus implementer agents, but adds an external cheap executor and a hard test gate. First step: run `npx cheap-agent`, pick OpenRouter, paste the key, check `claude mcp list`, run `/cheapag:allow` in a project, then `/cheapag:status` to see cost.

Take for your setup
  • Add the rule "the cheap executor must write a test that is red before and green after, and the orchestrator runs the tests itself" to the feature-build/testing skills for implementer?
  • Stop running Opus review on every green result: the author measured 3x tokens with no findings. Limit quality-reviewer to failing or missing tests?
  • Try `/cheapag:hook on` in one project and compare cost via `/cheapag:status` against the current Sonnet implementer.
  • Copy the escalation ladder cheap model → Sonnet → Opus capped at 15 tool calls into our agent files instead of choosing models by hand.

reanimate, a Claude Code skill, takes an animation apart frame by frame, writes the code and checks the copy against the original

reanimate is a Claude Code skill (MIT, 548 stars, created 2026-10-29). It takes an animation from a live site, screen recording, mp4, gif or Lottie file and rebuilds it in your project. The loop: 1) record in a headless browser at a fixed viewport and frame rate: video, frames, CSS and Web Animations, element positions per frame (for canvas/WebGL it traces GPU calls on a virtual clock); 2) write a spec, one row per element and property (start, duration, from/to, easing, stagger), with "?" where a value is not yet read; 3) build with what the project already uses: CSS, Framer Motion, GSAP or three.js; 4) verify: film the copy the same way and compare timing, easing and pixels, producing side-by-side sheets; 5) fix the largest difference and re-film, usually 2 to 5 rounds, with leftovers and reasons going into the report.

Fidelity follows your wording: "clone this animation" matches motion within 80 ms; "pixel-perfect" also matches appearance, ≤2% mean pixel mismatch. Reported: Vercel toolbar 417 of 417 frames identical, Resend cube 0.11% of pixels differ, most clones 30–90 minutes. Needs Bun 1.1+, macOS or Linux, about 250 MB on first run (ffmpeg, Chromium), no API keys. Springs are fitted from overshoot, not read from source; login pages and YouTube can't be recorded.

What is new for you is not the generation but the closed loop: record, spec, build, film the copy, measure against a numeric threshold. It is a pattern reusable for your Remotion pipeline and any UI work. First step: `npx skills add NiazMorshed2007/reanimate -g -a claude-code`, then `/reanimate the hero entrance on https://example.com, into components/Hero.tsx`.

Take for your setup
  • The skill verifies with numbers: ≤80 ms timing, ≤2% pixels. Add a similar "film the copy and measure" threshold check to the frontend skill for animations?
  • Its spec marks unmeasured values with "?" and caps fixing at 5 rounds with a report of leftovers. Borrow this in loop-design for fix-until-green loops?
  • Try reanimate on the Remotion pipeline: record a reference animation from a site and use the per-element, per-property spec as a scene brief?

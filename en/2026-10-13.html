01Simon Willison13.10

Huntley: instead of editing AGENTS.md, use a pre-commit hook that fails the commit and tells the agent which library to use

Simon Willison quoted Geoffrey Huntley's post "nobody should type code by hand anymore. here's what's left." (ghuntley.com/agency/) on 13 October 2026. The problem: the agent ignores his diagnostics library and calls observability modules directly. He could update AGENTS.md, but there would still be a gap between the written rule and actual behavior, and it would drift over time.

Instead he writes a pre-commit hook. The hook inspects the git diff for direct calls to observability modules that bypass his diagnostics module. If it finds one, the commit fails and a prompt is injected into the output telling the agent to use the library. He says this brings the agent to full compliance. The principle: a rule that can be checked mechanically belongs in a check, not in instructions.

You already have Claude Code hooks and CLAUDE.md, so "hook over instruction" is familiar. What's new is a git-level pre-commit hook that parses the diff itself and puts the fix directly into the error message for the agent. First step: pick one rule from CLAUDE.md that the agent keeps breaking (for example a direct call instead of your wrapper), and write a pre-commit script that searches `git diff --cached` for the violation and prints what to use instead.

Take for your setup
  • Take one often-broken rule from CLAUDE.md (direct call bypassing our wrapper) and turn it into a pre-commit hook over `git diff --cached`
  • Have the hook's error message tell the agent exactly what to use instead, as Huntley does
  • Add a rule to the settings-change skill: if a rule can be checked on the diff, make it a hook first and keep CLAUDE.md text only as a fallback

02GitHub13.10

Strands Box: a Rust agent sandbox with Dogwood policies and secret injection kept outside the agent

Strands Box (strands-agents/box, Apache-2.0, Rust, preview, created 2026-10-02, 393 stars) runs any agent binary under OS-level isolation and restricts files, programs and network. Setup is two files: box.toml (environment and direct grants) and policy.dw (Dogwood permit/forbid rules). Anything checked by policy is denied by default, and a matching forbid overrides a permit. Rules can depend on operation arguments, earlier actions and elapsed time: reading a file can cause a later HTTP request to be denied. The egress gateway checks connections and HTTP requests by method and path, and MCP tool calls by arguments. The gateway injects credentials itself (API keys or AWS SigV4), so the agent never sees the secrets. Decisions are logged as OTLP JSON (private/telemetry/records.jsonl). Limits: macOS on Apple silicon only, Linux "planned"; direct filesystem grants in box.toml are enforced by the OS and produce no Dogwood decisions. The page has no full policy.dw sample and no Claude Code instructions; the only worked example is the Strands CLI.

For you this is an alternative to Claude Code's built-in sandbox and permissions, especially for the Telegram bot and background agents, where keys (Keychain, Vault) are better kept outside the agent process. It also offers sequence-aware rules (read a secret, then no network), which PreToolUse hooks don't give you. First step on your Mac: curl -fsSL https://raw.githubusercontent.com/strands-agents/box/main/download.sh | sh, then ./box-core/box --version. The script installs into ./box-core and doesn't touch PATH. Next, try a low-risk agent such as claude -p in box.toml and inspect records.jsonl.

Take for your setup
  • Install Box (download.sh, ./box-core/box --version) and run a headless claude -p from one of your scripts inside it with default-deny network
  • Try credential injection via the egress gateway instead of passing Keychain/Vault tokens into the bot agent's environment
  • Borrow the Dogwood idea "after reading a secret file, deny HTTP" as a sequence-aware PreToolUse hook rule
  • Use records.jsonl (OTLP) as a denial log to tune minimal permissions for background agents

03GitHub13.10

claude-code-mods repo: hook-based plugins that show context, cache, limits and subagents live above the prompt

hamzafer/claude-code-mods (MIT, 225 stars, created 2026-10-02) is a marketplace of Claude Code plugins built on hooks. They draw live lines above the prompt. Among them: context-bar (context fill as a color-coded bar), token-weather (fill from Clear to Compact soon plus a prompt-cache countdown), cache-clock (time left before the cache goes cold, hit rate, tokens re-cached), usage-meter (5-hour and 7-day plan usage, reset countdown, session cost), agent-radar (`/radar`, one line per running subagent), review-watch (one line per running review, Codex or subagent, with a toast of findings at the end), replay-theater (`/replay`, last turn's edits one diff at a time), next-steps (2–3 likely next prompts on keys 1/2/3). There is also blast-radius: it holds `rm -r`, force pushes and migrations, shows what they would delete, and cancels after 60 seconds with no answer. It needs Claude Code 2.1.287+ (cache-clock: 2.1.251+ and Node). Some mods need Chrome, `gh`, the Codex CLI or macOS. The "My setup" mods (merge-gate, rulebook-guard) are built around the author's own tools, and the page advises reading community mods' code before installing.

You already have hooks, Codex review and your own observability skill, so what is new is ready-made statusline-style lines and a guard for destructive commands with a timeout. cache-clock and blast-radius are the most useful; the rest work as implementation examples. First step: `claude plugin marketplace add hamzafer/claude-code-mods`, then `claude plugin install cache-clock@claude-code-mods` and `claude plugin install blast-radius@claude-code-mods`. Restart Claude Code and run `/cache-clock setup`.

Take for your setup
  • Install cache-clock to see when the prompt cache goes cold and how many tokens were re-cached. It covers the session-cost questions your observability skill handles.
  • Install blast-radius and compare it with your PreToolUse hooks: it holds `rm -r`, force pushes and migrations, shows what they would delete, and cancels after 60 s with no answer. Adopt the timeout-cancel?
  • Borrow the review-watch idea: one live line per running review (Codex or subagent) and a findings toast at the end. Add it to your vendor-review skill?
  • Try usage-meter to watch the 5-hour and 7-day limits and session cost while a Workflow runs parallel subagents.

04GitHub13.10

answer-me-with-html skill: the agent writes a short Markdown draft and a CLI renders an offline HTML page with diagrams in ~50 ms

QingYunA/answer-me-with-html (MIT, 3.3k stars, repo created 2026-10-02) is a skill that makes the agent answer a hard question with one HTML page instead of a wall of text. The model writes only a Markdown draft with frontmatter and component blocks (flow, er, sequence, tree, timeline, limits, annot, kv, callout, ask, real code quoted via src= and lines=, tables with ok/no/warn cells). A bundled `am` CLI (Node 20+, marked and dagre already inside) handles layout, CSS and SVG. The point is token savings: in the author's count of 9 hand-written pages, 47% of tokens were SVG coordinates, 15% CSS, 17% tags and only 21% text. The project's own benchmark (3 topics × 3 runs, Sonnet 5.5 in Claude Code): 612 output tokens on average vs 4,893 for hand-written HTML, median 12 s vs 31 s; total cost drops only ~15%. On a draft error the CLI returns the line, the component and a correct example. There are blueprint/shadcn/paper themes, per-panel comments, an `ask` block with the agent's suggestion preselected, and a Reply button that bundles answers into one message. Pages are saved in ~/.answer-me-with-html/pages/. An always-on mode (off by default) appends a 2–4 panel mini page with a file:// link to answers; you enable it with a rule in CLAUDE.md, and it makes no pages in plan mode.

You already publish artifacts from Claude Code and use plannotator to annotate HTML, so what is new is the pattern of the model writing a compact DSL with a deterministic renderer, plus the interactive `ask`/Reply loop. First step: `/plugin marketplace add QingYunA/answer-me-with-html`, then `/plugin install answer-me-with-html@answer-me-with-html`, and ask it to "Explain the TCP three-way handshake" or map your repo's modules.

Take for your setup
  • Install the plugin and run it on one real code question (a module map of a repo), then compare with our artifacts flow.
  • Add the always-on rule from the README to one project's CLAUDE.md for a week and see whether it bloats replies.
  • Borrow the pattern of the model writing a compact DSL with a deterministic renderer for our reports (digest, observability): is page.html generated differently now?
  • Take the `ask` block idea (preselected suggestion plus a Reply button that bundles answers) for the grilling and council skills.

05GitHub13.10

Claude Code plugin shows images and plays videos inside the Ghostty terminal

claude-show-your-work is a plugin (MIT, 173 stars, created 2026-10-08) that gives Claude two tools: show_image and show_video. Images are drawn in the Ghostty terminal and never sent to the model, so they cost no tokens. Video is decoded with ffmpeg at up to 12 frames per second, window width up to 2400 px, capped at 900 frames. The oldest files are deleted once the cache reaches about 1 GB.

Notable part: Claude tests a feature with Playwright, records the run and plays it in the chat. A list of changes sits beside it, clicking one jumps to that moment, and checks turn green or red as the video reaches them. For bug fixes, compare mode plays the old and new versions side by side in sync. Parameters: path, compare, title, url, changes [{title, at}], summary [{label, ok, passed, total}], with summary limited to three lines. A page can be shown at desktop, tablet and phone widths in one image.

For you: Playwright and Chrome automation are already in your setup; what's new is showing the result in the terminal with synced before/after. Requirements: macOS, Ghostty (the repo's About mentions kitty too), Claude Code 2.1.287+, ffmpeg. In tmux you need set -g allow-passthrough on. The plugin auto-updates only from its own repo and sends anonymous telemetry; turn them off with env SHOW_YOUR_WORK_AUTO_UPDATE=0 and SHOW_YOUR_WORK_TELEMETRY=0.

First step: /plugin marketplace add https://github.com/iamumeransari/claude-show-your-work.git#releases, then /plugin install show-your-work@iamumeransari.

Take for your setup
  • Install the plugin and run /show-your-work tour, then try the synced before/after on one of your own bug fixes.
  • Add a rule to the testing skill: after a Playwright run, call show_video with changes and summary [{label, ok, passed, total}] so the result is visible without opening files.
  • In the frontend skill, show a page at desktop, tablet and phone widths in one image via show_image instead of separate screenshots.
  • Set SHOW_YOUR_WORK_AUTO_UPDATE=0 and SHOW_YOUR_WORK_TELEMETRY=0 in the settings.json env before first use, if you don't want auto-update or telemetry.

06PyCoder's Weekly13.10

Python 3.15 released Oct 9: lazy imports, UTF-8 by default, Tachyon sampling profiler

This PyCoder's Weekly issue is a link roundup; the substance is Python 3.15, released on 9 October 2026. New: PEP 810 — `lazy import json` defers loading a module until first use (module scope only; enable globally with `-X lazy_imports=all` or `PYTHON_LAZY_IMPORTS`). PEP 686 — UTF-8 is the default for I/O without `encoding` (revert with `PYTHONUTF8=0`). PEP 798 — `[*L for L in lists]`. Built-in `frozendict` (PEP 814) and `sentinel` (PEP 661), `TaskGroup.cancel`, tomllib with TOML 1.1. PEP 799: a `profiling` package with the Tachyon sampler for running processes (up to 1,000,000 Hz, wall/CPU/GIL/exception modes, flame graphs, pstats); the `profile` module goes away in 3.17.

Miguel Grinberg's benchmark: fibo(40) takes 6.94 s on 3.15 vs 7.17 s on 3.14, so almost no gain. The JIT is 20–28% faster. The free-threading build with 4 threads is about 4.5x faster than the standard build (fibo) and 1.74x (bubble), but single-threaded bubble is slower (0.74x).

For you: asyncio and TaskGroup are familiar; what is new is `TaskGroup.cancel`, Tachyon, and lazy imports for faster Celery worker and CLI startup. The risk is UTF-8: check containers with a non-default locale. First step: run your tests on 3.15: `python3.15 -X lazy_imports=all -m pytest`.

Take for your setup
  • Add a Python 3.15 job to CI plus a separate run with `PYTHONUTF8=0` to catch encoding differences in files and logs.
  • Try `lazy import` for heavy modules (pandas, SQLAlchemy models) in Celery worker and CLI entry points and measure startup time.
  • Attach Tachyon (`profiling.sampling`) to a live FastAPI or Celery process instead of cProfile and capture a flame graph.
  • Replace hand-rolled `_MISSING = object()` with the built-in `sentinel`, and immutable config dicts with `frozendict`.

01GitHub14.10

The effortless plugin picks reasoning effort per prompt in Claude Code and shows a prompt-cache countdown

effortless (MIT, by HeyCubit) is a hook-based Claude Code plugin. Before each prompt a "judge" (default Haiku 5.5 on your own login; optionally Jev from TypeSafe via API key, with Haiku as fallback) sets the effort: simple question gets Low, hard task gets High. Short replies like "ok"/"yes" keep the current effort. Changing effort by hand turns Auto off. It only acts on Opus 5.5 and Sonnet 5.5; on Fable 5.1 and older models Auto pauses. A bar above the prompt shows effort, model, context fullness in % and a countdown until the prompt cache goes cold. When the cache is cold on a big chat it offers Compact or Handoff (Quick is a fast summary; Full also checks git and writes HANDOFF.md). Summaries come from Haiku 5.5, falling back to normal compaction. It warns when usage limits pass 80% and enables Save mode, capping effort at Medium.

Author's numbers (run 2026-10-10, 4 tasks × 3 runs, all 12 correct): on Opus 5.5, $0.149 per task versus $0.190 at medium, $0.209 at high, $0.257 at xhigh (21/29/42% less). Judge accuracy on 73 labelled cases: Haiku about 92–93%, Jev 99%, always-medium 44%. Author's caveats: small sample of mostly easy tasks, savings shrink on hard ones, tests used fresh API chats rather than long subscription sessions, and Haiku misses "yes/thanks" after hard work.

For your setup this is closest to pinning effort per agent file (high/xhigh), but applied to the main session, plus cache and context visibility you don't have. To try it: `/plugin marketplace add HeyCubit/effortless`, then `/plugin install effortless@effortless`, `/reload-plugins`, `/effortless setup`. The terminal CLI may need `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`. A Jev key entered in the setup guide is stored in plain text in `~/.config/jev/.env`.

Take for your setup
  • Install effortless for a week and compare spend against manual effort — we have no auto effort selection for the main session.
  • Borrow the prompt-cache timer idea: a hook or status line showing time left before the cache goes cold, warning before returning to a large chat.
  • Add a Full handoff variant to our flow: summary plus git check plus writing HANDOFF.md, with the summary done by Haiku 5.5 as the plugin does.
  • Copy the Save mode rule: when usage limits pass 80%, cap effort at Medium.

A game dev shows how to make a game a harness for agents: seed, odiff on screenshots, commands, samply

Kyle Kukshtel (post of 2026-10-10, based on a talk in Calgary on 2026-09-12) argues that LLMs struggle with games because much of a game is not code (assets, scenes, tuning data), and an agent needs an environment where it can act, observe and verify itself. His techniques: one seeded source of all randomness so any state can be recreated; the engine's built-in screenshot API plus toggles for UI and gameplay layers; odiff (CLI) produces a diff image and a similarity score (example "85% similar"), which after cropping gives a quantitative metric each turn instead of the model eyeballing noisy before/after frames; save/load of exact state from day one; one `Thing` type for everything; every state change as a serializable command (replay bugs, puppet the running game without compiling); static tuning data outside code; simulation as a separate engine-free library; samply dumps profiles as text so the agent runs its own measure-and-fix loop.

He says the full loop (change, simulation, screenshot diff, profile) can run in seconds within one agent turn. The HN thread adds: headless runs for parallel testing, bot players for balance, cross-platform state checksums in CI, metrics exported as time series. Critics: models break code on small edits, `Thing` won't meet performance budgets without ECS, and game "feel" is hard to put in words.

Games are secondary for your setup, but the principle carries over to the Remotion pipeline and the bots: give the agent a numeric check of its output. First step: install odiff and run it on a frame from bot/video/ before and after an edit to Gfx.tsx.

Take for your setup
  • Numeric frame check: run odiff before/after graphics edits in the Remotion pipeline (bot/video); add a compare-with-threshold step to the montage skill?
  • Seed and reproducibility: pin one seed in video/graphics generation so an agent can replay exactly the same state when debugging; add it to the montage tests?
  • Profiles as text: dump profiles of slow scripts (montage.py) as text and hand them to the agent for a measure-and-fix loop; create a skill for it?

03GitHub14.10

VibeStart: a CLI that scaffolds a TypeScript project for AI agents with AGENTS.md and CI-verified stack combinations

VibeStart (MIT, 151 stars, repo created 2026-10-04) is a CLI and web studio that composes a full-stack TypeScript project from chosen layers. Layers: React SPA (TanStack Router), TanStack Start or Next.js; Electron and Expo; Hono or the framework's own backend; oRPC/OpenAPI; PostgreSQL, MySQL, SQLite, MongoDB; Drizzle, Prisma, Mongoose; Better Auth; Docker; shadcn + Tailwind 4; Vitest, Playwright or TesterArmy; Vite+, Oxlint, Knip. The output is a plain repo with no runtime dependency on VibeStart.

For agents it ships AGENTS.md (where and how to make changes) and one command, `vp run ready`: types, lint and tests, fastest first. The CLI rejects impossible combinations and names the smallest fix. Before each release every supported combination and every set of three choices is installed, type-checked, linted, tested, browser-tested and built in CI; passes are recorded with fingerprints on the `verification` branch. `upgrade` does a three-way comparison of the original template, your project and the new template and previews before writing, leaving app code alone. The README mentions neither CLAUDE.md nor hooks.

For your setup: you already have skills, hooks and subagents; what's new is a ready starter with one fast gate for the agent. Useful when spinning up a new TS project where the agent gets feedback within seconds. First step: `npx vibestart-cli my-app --list`, then `--dry-run`; or `npx skills add VinkyDev/vibestart --skill vibestart`.

Take for your setup
  • Adopt the single `vp run ready` gate (types, lint, tests, fastest first) as a required check in CLAUDE.md and a Stop hook for TS projects?
  • Run `npx vibestart-cli my-app --dry-run` and compare the generated AGENTS.md with our CLAUDE.md - anything worth borrowing?
  • Add a rule to the feature-build skill: reject impossible combinations with the reason and the smallest fix, as the CLI does?

04Simon Willison13.10

llm-gemini 0.35 adds Gemini 4 Argon support: $2/$10 per million tokens, price doubles on 1 December

Simon Willison released llm-gemini 0.35, a plugin for the `llm` CLI, which now supports Google's new Gemini 4 Argon model. Argon became available on 13 October 2026 through the Gemini API and for customers of Google's $100/month plan. It currently costs $2 per million input tokens and $10 per million output tokens. That matches GPT-6 Sol and is half the price of Claude Opus 5.5. On 1 December the price doubles to match Opus 5.5.

Willison stresses that per-token price says little about real cost. What matters is how many tokens a model needs to finish a task inside an agentic harness. Artificial Analysis puts the cost of running its benchmark on Argon at $2,407. That is close to GLM-5.3 and well below the latest OpenAI, Anthropic and Meta models. He expects Argon to stay slightly cheaper than GPT-6 Astra even after the increase. The SVG pelican-on-a-bicycle at low, medium and high settings all came out excellent, and the high one cost 17.166 cents. The page lists no plugin options and says nothing about agentic coding behaviour, so it tells you little about coding quality.

For you this is a reason to try Argon as an extra reviewer next to Gemini CLI while the $2/$10 price lasts. First step: `llm install -U llm-gemini`, then `llm models` to find the Argon identifier. The post does not give the exact model name, so look it up in that list.

Take for your setup
  • Add Argon to the vendor-review skill as another reviewer via `llm`, while the $2/$10 price holds until 1 December.
  • Compare cost by tokens per task, not price per token: in the observability skill, measure Argon against Opus 5.5 on the same review.

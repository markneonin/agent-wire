dev-quality-gates: a curated one-tool-per-job list of quality checks, with an adoption prompt for agents

mokevnin/dev-quality-gates (159 stars, created 2026-10-23, CC0) is not an awesome-list but a curated one: one tool per job, with limitations, review date and sources recorded in tools.json. Criteria: the tool must exit non-zero on a violation, run non-interactively, give machine-readable output and safe autofix. Fast Rust-native tools are preferred (Ruff, Oxlint/oxfmt, Mago, rumdl). Categories without a verified pick stay empty (under review: Trivy after a March 2026 compromise, Brakeman over its licence, Semgrep/Opengrep). Picks include Knip, dependency-cruiser, ty, deptry, import-linter, golangci-lint, cargo-deny, squawk (Postgres migrations), oasdiff (API breaking changes), diff-cover (coverage of changed lines), Betterleaks (secrets), OSV-Scanner, lychee, typos, mise for tool versions, hk (~170 ready git-hook steps) and commitlint. The one Claude Code-specific entry is agnix: it lints CLAUDE.md, AGENTS.md, SKILL.md, hooks and MCP configs, exits 1 on errors, and on warnings with --strict.

The key part for agentic work is docs/adopt.md, written for an agent. From the repo root you ask the agent to read it, pick only fitting entries, show the plan before editing, wire checks into hooks and CI, and verify each check can actually fail. You already have ast-grep (also listed there, for custom rules). New for you: agnix to audit your many skills and hooks, diff-cover, and docs/patterns.md. First step: install agnix and run it over ~/.claude and project CLAUDE.md files, and give docs/adopt.md to an agent in one project.

Take for your setup
  • Run agnix over ~/.claude and project CLAUDE.md/SKILL.md/hooks to catch config errors in skills and MCP (exit 1, --strict for warnings) — add it to settings-cleanup?
  • Add diff-cover to the testing skill and a Stop hook: fail when changed lines lack test coverage
  • Take the adopt.md rule 'verify each check can fail' into the process/feature-build skills: the agent must show a new gate going red on known-bad code
  • Try hk (hk.pkl) with mise for parallel git hooks and pinned tool versions instead of hand-written hooks

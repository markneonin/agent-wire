FastAPI 0.164.0 adds configurable request body size limits

FastAPI 0.164.0 (PR #16781 by @tiangolo) adds configurable request body size limits. The release page itself has just that one line; the details below come from the PR description. A max_body_size setting can be set on the app, on routers and on individual path operations. A separate optional form_limits setting with max_fields, max_files and max_part_size limits form parsing. By default bodies are unlimited until max_body_size is set; form_limits defaults match Starlette's existing form parser defaults (the actual values are not given in the source). What response a client gets when a limit is exceeded was not stated in what I read. Docs: /advanced/request-body-limits/.

For your backend this is protection against oversized uploads and forms with huge numbers of fields, without custom middleware or an nginx-only limit. You can set a global cap on the app and raise it only on the file-upload endpoint. FastAPI had no built-in equivalent before, so this is new for you. First step: upgrade to 0.164.0, set max_body_size on the app or a router, and write a test that checks which status is returned when the limit is exceeded.

Take for your setup
  • Set max_body_size on the app as a global ceiling, and raise it only on file-upload endpoints via the path operation.
  • For form endpoints, set form_limits (max_fields, max_files, max_part_size) explicitly instead of relying on implicit Starlette defaults.
  • Add a pytest test for exceeding the limit: check the response status and that the handler is not called, since the source doesn't specify this.

02FastAPI releases18.11

FastAPI 0.165.0 adds configurable form parsing limits

FastAPI 0.165.0 (released 18 Nov 2026) lists one feature: configurable form parsing limits (PR #16784 by @tiangolo). The release notes and the PR page don't name the parameters, defaults or show example code. The only pointer is that the PR changes the docs page advanced/request-body-limits, which probably describes the setup. I couldn't open that page, so I'm not quoting parameter names or numbers.

The release also mentions an official FastAPI skill for coding agents that helps them use new features and recommended patterns for the installed version. Install it in a project with uvx library-skills (see the Develop with AI docs).

Why it matters: if your FastAPI services have endpoints with Form/UploadFile, form parsing limits protect against oversized or too many fields and files. First step: upgrade to 0.165.0, read advanced/request-body-limits in the docs, and check which defaults now apply to your forms so the upgrade doesn't break uploads.

Take for your setup
  • Run tests for Form/UploadFile endpoints on 0.165.0 to check whether default limits changed behavior
  • Install uvx library-skills in a FastAPI project and see what the skill recommends for the installed version
  • Read advanced/request-body-limits and set explicit form limits on endpoints that accept uploads

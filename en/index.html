rsrc: a CLI that lets agents read X, Reddit, YouTube and other sites web search covers poorly

rsrc returns one JSON object per command, with text, author, date and engagement. It covers X (posts, threads, replies, timelines, search), Reddit, Hacker News, YouTube (with transcripts), public LinkedIn posts with comments, and App Store listings and reviews. Read-only, no API keys, MIT. Each site's results are fetched fresh, with no merged ranking or cache. Exit codes: 0 means results, 66 none, 2 bad arguments or setup, 1 a runtime failure (rate_limited, blocked, not_found). The author reports it was 2–12x faster than Agent-Reach on X and Reddit, had no false success in 264 runs, and found at least 4 URLs per topic that web search missed in a five-topic test. It's early one-person software, with live sources tested only on macOS. Its unofficial routes can break. X, Reddit and LinkedIn restrict automation, and X or Reddit may limit your account.

For you, it's one command for these sites, alongside web search and separate from Claude in Chrome. X search needs your session: Ego Lite, the auth_token and ct0 cookies in ~/.config/rsrc/x.env (mode 600 or stricter), or the experimental rsrc x connect through Chrome. Reddit search and live threads need Ego Lite; without it, reddit read uses the public Arctic Shift archive. Start with no login (Python 3.11+, uv): uv tool install git+https://github.com/SamuelZ12/research-sources, then rsrc check hn appstore.

Take for your setup
  • Add the rsrc skill (npx skills add SamuelZ12/research-sources) and call it from your deep-research skill alongside web search?
  • Add YouTube transcripts to research via rsrc youtube read? It needs yt-dlp and deno: brew install yt-dlp deno.
  • Adopt rsrc's contract in your own agent scripts: a separate exit code 66 for empty results and named errors for failures, so a failure can't pass as "nothing found"?
  • If you connect X, add a skill rule: keep request volume low, and note that a search order including x-graphql can switch to your account after a failure?

Clipy: an open-source screen recorder that turns video into a text file with screenshots for AI agents

Clipy (Apache-2.0, repo created Nov 22, 274 stars) records screen and voice. People get a share link; agents get `recording.arec`: Markdown with transcript, clicks, key moments, timestamps and screenshots (AREC format 1.4). Local rules pick moments from highlights, drawings, clicks and pointer pauses. An optional model adds spoken cues like “it breaks here”, and ffmpeg grabs one frame per moment. Speech can be transcribed on-device (Apple speech on macOS, Parakeet or Whisper elsewhere); YouTube and Loom captions work too. The desktop app covers macOS and Windows; Linux is CLI only.

You already have Whisper. What's new is a ready-made path from video to agent context: `/watch` takes a YouTube link, Loom link or local file plus your question. On macOS an agent can also record a chosen window and add marks. The app must be running, and the first take asks for your consent. With Ollama or LM Studio and on-device transcription, everything stays on your machine. A hosted model gets transcript text, click labels and a bounded sample of pointer and key events, but no video or screenshots. Hosted transcription sends audio to the provider. First step in Claude Code: `/plugin marketplace add clipy-recorder/clipy`, `/plugin install watch@clipy`, then `/watch ./demo.mov summarize this`.

Take for your setup
  • Install the `watch@clipy` plugin so your agent can handle requests like “list every bug the speaker points out” on a Loom link or local file?
  • Try reporting bugs to your agent as a narrated recording: run `clipy record --local --max 120`, then give it the `recording.arec` path the command prints?
  • Add run recording to a macOS UI check skill: `clipy session start --local --source mac-screen`, `clipy mark "..."` at each step, then `clipy session stop --local`?
  • For private screens, make on-device transcription plus `CLIPY_MODEL_PROVIDER=ollama` and `CLIPY_MODEL` your Clipy setup, so nothing goes to hosted providers?

PopAgent: a local web UI for pi, Codex, Claude Code, OpenCode and DSH that lets you correct an agent mid-turn

PopAgent (MIT) shows the agent's reasoning, tool calls, changed files, tokens and cost in the conversation. There is no database: sessions stay the engine's own files. Mid-turn correction is native only in pi, the default engine. For Claude Code, Codex, OpenCode and DSH it is "stop-and-resend": the turn stops and your correction is sent again. Claude Code connects over ACP via `claude-code-acp`: it shares sessions with the `claude` CLI, approves tools per call and offers model choice, but no reasoning levels or subagents. The subagent panel is pi-only. There are also cron tasks with a timezone, voice, a plan graph, Web Push with a PWA, and macOS app control.

Your Claude Code would get a web window and phone access here, with fewer capabilities; the text I read doesn't say whether your skills and hooks work in this mode. The more interesting use is one UI for several engines. It listens only on 127.0.0.1 by default. Remote access needs `-H 0.0.0.0` and a password set on the host itself, and 3 failed logins lock you out for 30 minutes. First step: with Node ≥ 22.19, run `npm -g install pop-agent`, then `pop-agent`. There is also an Apple Silicon `.dmg`, but it is ad-hoc signed, so Gatekeeper may block the first launch.

Take for your setup
  • PopAgent's scheduled runs can't write files unless the task explicitly allows it: make that a rule in your loop-design skill for your `claude -p` and cron agents?
  • There, a turn that exceeds the watchdog limit is interrupted and recorded as failed: check that your background and headless runs behave the same way?

v2: version control for video projects built with coding agents, footage and renders included

v2 (MIT license) versions a video project that Claude Code, Codex or another agent works on. Code and text go into git, while footage, music and renders go into v2's own store. The README says any version comes back exactly. `v2 init` sets up the project and teaches the agent to save a version after each edit, with the prompt that asked for it. `v2 log` lists versions. `v2 diff` opens them in the browser, where you can watch one, compare two and leave timed comments for the agent. `v2 restore 3` brings back version 3 as a new version. `v2 push` uploads to v2.video and prints a private link. It needs git and ffmpeg, and the installer covers macOS and Linux. The README doesn't explain how the store works, what `init` changes, how comments reach the agent, who can open the link, or whether there are limits.

You already have git. What's new for your Remotion and `montage` work is one history for code and media, tied to prompts, plus visual comparison of versions. First step: `curl -fsSL https://v2.video/install.sh | sh`, then `v2 init`. Read the script first, and run `init` on a copy of a project so you can see what it changes. `v2 push` sends the project to an external service, and a local trial doesn't need it. Releases are signed, and `v2 update` checks the signature before replacing the binary. Building from source needs Go and Node 24, and `go install` doesn't work.

Take for your setup
  • v2 keeps each version with the prompt that asked for it. Add a v2 version save after every edit to your `montage` skill?
  • `v2 diff` compares two versions in the browser and takes timed comments. Try it as the review step for `montage` and Remotion videos, and check how the comments reach the agent?

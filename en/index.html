01Claude Code releases09.11

Claude Code 2.1.321: Fable 5.2 becomes the default Fable model, --settings for remote-control, and a batch of sandbox and hook fixes

v2.1.321 shipped on 9 November 2026. It adds Claude Fable 5.2 (`claude-fable-5-2`), now the default Fable model: 1M context, $8/$40 per Mtok, $0.20/Mtok cache reads. Saved Fable 5.1 picks move to `fable` (immediately on Pro/Max, on Team/Enterprise once the org allows it); `/model claude-fable-5-1` switches back. The other new item: `claude remote-control --settings <file>` applies a settings file to every session it starts; if the file changes, no new session starts until you restart `remote-control`.

The rest is fixes. Security: MCP OAuth no longer sends refresh tokens to another host on a redirect; a read-only Bash command no longer runs outside the sandbox without a prompt; deny rules now apply to `cp`/`mv` into a directory, including `/bin/cp`; Bash permission checks no longer judge a write from the wrong folder. Hooks: a PreToolUse `ask` is no longer lost when another hook's `defer` finishes first, a large hook output no longer points to another hook's file, and `PreToolUse` `mcp_tool` hooks with an answer over 16 MiB now refuse the call. Also: `claude -p` on Linux now prints an error and exits 1 when NFS losses drop transcript lines; fast mode tries standard speed on the same model first; several Bash commands sent at once no longer run in the wrong folder; background command notifications over 1,000 characters show only the start and end, saving context; headless sessions reload skills when files change (turn off with `CLAUDE_CODE_PLUGIN_DIR_WATCH=0`). For you the hook, sandbox and `-p` fixes matter most, since they touch your PreToolUse hooks and headless scripts. First step: update, run `/model` to confirm Fable 5.2 appears, and check that your PreToolUse hooks using `ask`/`defer` behave as expected.

Take for your setup
  • Re-check PreToolUse hooks: an `ask` is no longer lost when another hook's `defer` finishes first, so verify our ask/defer hooks behave as intended after the update
  • In `claude -p` scripts, handle the new exit code 1 when transcript lines are lost (NFS) and check it in wrappers
  • Try `claude remote-control --settings <file>` for the Telegram bot sessions: one settings file for every session it starts (restart remote-control after editing the file)
  • Run `/model` and decide whether to move the most expensive agents to Fable 5.2 ($8/$40, $0.20/Mtok cache reads, 1M context); compare against Opus 5.5 on one task

Claude Fable 5.2 merges duplicated code when the prompt says the code is its own

Simon Willison quoted the "Say who owns the code" section of Anthropic's "Prompting Claude Fable 5.2" docs (10 Nov 2026). The point: the model responds closely to what the prompt says about who owns the code. If ownership is not mentioned, or the code is framed as someone else's, then on small coding tasks it adds to the existing structure, even when that means repeating code.

The recommended sentence: "This codebase is yours: what it's for and how it's built are your call, and you'll keep building on it." With it, the model merged repeated code in about half of the tries; without it, in under one in ten. This is Anthropic's measurement on small tasks, not a guarantee.

For your setup it is a one-line change: if you want agents to clean up duplication as they go, put the sentence in CLAUDE.md or the implementer brief. If you want a minimal diff in legacy or third-party code, leave it out and limit the scope explicitly. First step: add the sentence to an implementer brief on one feature and compare the diff with a normal run. Source: platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-2#say-who-owns-the-code

Take for your setup
  • Add the code-ownership sentence to the implementer agent brief (subagents skill) for your own projects where merging duplicates is wanted
  • Add an explicit switch in the feature-build skill: "this code is yours" for own repos versus "minimal diff" for third-party or legacy code
  • Run an A/B on one task with duplicated code (with and without the sentence) and compare the diffs through quality-reviewer

Floorplan: a Claude Code and Codex plugin that draws an interactive plain-English map of your codebase

Floorplan (haydenschmitty/floorplan, MIT, v0.2.2, created 2026-10-27, 306 stars) is a plugin for Claude Code and Codex. Plain Node 18+ scripts with no dependencies collect files, imports, routes and web requests; Claude or Codex decides what the app's parts are and describes each file. The output is floorplan/index.html: zoomable views from the whole app down to one file, frontend requests matched to server endpoints (including across repos), a "start from a screen" view, an Ask bar that answers with a mini-map and step-by-step walkthrough, a Health check (hardcoded secrets, showing where but never the values; unauthenticated endpoints; unused and oversized files, each with a fix prompt) and a Recent work board showing what the AI changed. Updates re-read only changed files, and large projects are split across parallel helpers. No API keys, it runs on your plan. The floorplan/ folder and a section in CLAUDE.local.md are not committed; your code, .gitignore and CLAUDE.md are untouched. Edits to architecture.json and descriptions/ survive updates. No analytics, and the server accepts only local connections.

You already have the codebase-memory MCP, the code-investigation skill and artifacts; Floorplan is more a visual layer for the human than memory for the agent. New for you: the Health check with ready fix prompts and the frontend-request-to-endpoint matching. Limit: the Ask bar needs the Claude Code CLI. First step: `claude plugin marketplace add haydenschmitty/floorplan`, then `claude plugin install floorplan@floorplan`, start a new session and say "Make me a floorplan of this app."

Take for your setup
  • Install the plugin on one project and compare its Health check (secrets, unauthenticated endpoints, unused files) with our /code-review: what does it find extra?
  • Borrow the "fix prompt for every finding" idea in our code-investigation or observability skill, so a finding turns straight into a ready brief for a subagent.
  • Try "If I change the users table, what breaks?" as an impact-analysis prompt before feature-build and compare the answer with codebase-memory.
  • Copy the "generated output is never committed" pattern: write artifacts to CLAUDE.local.md and a self-ignoring folder so the shared CLAUDE.md stays untouched.

RudderStack open-sources DevBox: an autonomous ticket-to-draft-PR agent, one sandbox per task, no real secrets inside

DevBox (MIT, rudderlabs/devbox, repo created 2026-10-27) is a harness you run in your own infrastructure: hand it a ticket and it plans, writes code, runs tests, reviews its own diff and opens a draft PR. RudderStack says it merges about 35% of its internal PRs, with an 80% merge rate. Pipeline: orientation → planning → plan review (a gate: no code is written until the plan passes) → implementation → self-review → draft PR with a "knowledge commit".

Architecture: a control plane (stores tasks, starts one sandbox per task through OpenSandbox, makes no LLM calls), a harness inside the sandbox built on DeepAgents, and iron-proxy between the sandbox and GitHub/the LLM. The sandbox holds only placeholder tokens; the proxy swaps in the real ones on the way out and allows writes only to the repos you list. Keys live in Keychain/libsecret or env. PR comments are read only from trusted users (empty by default). It supports OpenAI's Responses API and Anthropic's Messages API, with model and effort set per stage. GitHub only; tasks come from the CLI and Linear; it never pushes to main or merges. Needs Docker with 8 GB, Bun 1.4.4+, about 15 minutes to set up.

Much of this overlaps with your Workflow, subagents and worktrees. What is new for you: placeholder tokens in the sandbox with an egress proxy injecting the real key, and a hard plan-review gate before any code. Your secrets skill covers the Keychain side but not isolation. First step: git clone https://github.com/rudderlabs/devbox.git, cp devbox.config.example.json devbox.config.json, bun run quickstart, then bun run devbox create "Add a /health endpoint to your-org/your-repo".

Take for your setup
  • Proxy-held secrets: for headless `claude -p` runs and bots, give the agent only a placeholder token and let an egress proxy inject the real one, with a write allowlist of repos. Add this as an option to the secrets skill?
  • Plan gate: in feature-build, block implementation until a separate reviewer passes the plan (like DevBox's plan review), as a hard condition rather than a guideline?
  • Trusted-author allowlist: if the bot reads PR or chat comments, accept them only from an explicit allowlist that is empty by default. Add to the bot's rules?
  • Knowledge commit: add a separate commit with the task's learnings to each draft PR. Try it as the final step in task-context?

Ryugi: a Superpowers fork where the agent draws UI mockups and gets them approved in the browser before spec and TDD

Ryugi (流儀) is a workflow plugin for coding agents, forked from Superpowers v7.0.0. The chain is brainstorm → mockups → spec → TDD → verify, and the skills trigger on their own. The idea: the agent stops describing UI and shows it. Artboard draws several design options side by side; you can comment on any part and answer in the terminal (`q1 → b`). Document is a design doc with diagrams, charts, tables and code: you comment on sentences, and in-place edits merge with the agent's. HTML gives one-page prototypes with real controls like sliders, and control values persist when the agent rewrites the page. Verify puts screenshots of the built result next to the approved design: pass or reject, and rejected work comes back fixed. Library is a local artifact browser: `npx ryugi-artifacts`. It installs on Claude Code, Gemini CLI, Codex, Cursor, OpenCode and about 10 other harnesses. Skills are MIT, the artifacts app is AGPL-3.0. Repo created 2026-10-19, 207 stars, 352 commits. The page doesn't detail the spec, TDD or subagent rules (they're in docs/workflow.md).

You already have superpowers, review-page, feature-build and plannotator, so the brainstorm → spec → TDD loop is familiar. What's new is the visual layer: options compared side by side, comments on fragments, and a final check of the screenshot against the approved mockup. First step: `/plugin marketplace add Innei/ryugi`, then `/plugin install ryugi@ryugi-dev`, and in a scratch project send `Let's make a react todo list`. Or just run `npx ryugi-artifacts` to see the library.

Take for your setup
  • Add a Verify stage to feature-build/review-page: screenshot of the implementation next to the approved mockup, pass or reject, as in Ryugi.
  • For UI tasks, have review-page show 2-3 design options side by side with terminal answers like `q1 → b` instead of text descriptions.
  • Try `npx ryugi-artifacts` as a local artifact library and compare it with our Artifacts and backlog-hub.

/effects skill for Claude Code adds face-tracked effects to talking-head clips, with layers sitting behind your head

Vibha-Ramprakash/claude-video-effects (MIT, 309 stars, 7 commits, created 2026-10-22) is a single Claude Code skill. You drop a vertical clip with you in frame into the chat and type, for example, `/effects orbit from 3 to 6 seconds`. Claude checks a few frames, drafts a plan for you to approve, then renders `yourvideo_effects.mp4` next to the original, leaving the audio untouched. The repo title says 36 effects, the README says 45 (orbit, spotlight, comment-box, glass-widgets, tier-list, match-cut and others). Effects can be stacked in one request, and timing can be given in words, including by a spoken phrase.

Under the hood: OpenCV YuNet for face tracking, MediaPipe Selfie Segmenter for the person cut-out (which is what puts layers behind the head), ffmpeg and Python, 1080p by default, 4K on request. Models are in `models/`, scripts in `scripts/`, fonts with licenses in `fonts/`. You supply the real numbers for charts and counters; orbit, noise, phone-fan and profile-wall need a folder of screenshots. No sound or captions are added.

For you this isn't new mechanics (you already have skills, Remotion and montage). It's a ready example of a pipeline skill: SKILL.md + scripts + models in one repo, with a "plan for approval → render" flow. It's a useful source of tracking and person-mask tricks for Remotion. First step: `git clone https://github.com/Vibha-Ramprakash/claude-video-effects ~/.claude/skills/effects`, restart Claude Code, and run `/effects orbit` on a short clip.

Take for your setup
  • Pull the YuNet + MediaPipe Selfie Segmenter combo from the repo into our Remotion pipeline as a "text behind the head" layer, as a separate step in the montage skill?
  • Copy the skill layout (SKILL.md + scripts/ + models/ + fonts/ in one repo, auto-installing dependencies on first run) for our skills that have heavy dependencies?
  • Adopt the "Claude inspects a few frames and shows a plan for approval before rendering" step in the montage skill ahead of expensive renders?

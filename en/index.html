Anthropic redesigned Claude Code Projects: a coordinator hands a goal to parallel cloud threads

The announcement page is dated September 17, 2026; HN is discussing it in November. A project now takes a goal, not just a folder of context. Each project has a coordinator that breaks the goal down, routes briefs to new or existing worker threads, reviews outputs and assembles the result. Each thread is a Claude Code cloud session on its own branch and repo copy; overlaps resolve as ordinary merge conflicts. Threads can split work further with subagents, loops and workflows, open PRs and run tests. The project has shared memory (reasons for decisions, schedule changes) and a library of files and artifacts. You can pick model and effort for the coordinator and workers, see per-project usage and tune check-in frequency. The article's example: retire a v1 endpoint across API, web and mobile, one thread per repo, then a report on which PRs must merge first. Beta is for select Pro/Max users with no existing projects; waitlist at claude.com/form/projects. Local execution is "coming very soon". In the discussion, Boris Cherny of Anthropic said the coordinator adds under 10% token overhead. Criticism: cloud-only with no local files, a weak default coordinator, one query spawned seven subagents and drained a Max plan, little visibility.

For you this is mostly UX over what you already have: Workflow, worktree writers, task-lead and SendMessage. Three things are new: shared project memory across threads, phone steering, and work that continues while your machine is off. It is cloud-only for now, while your setup relies on local hooks and MCP, so it is no replacement. First step: join the waitlist at claude.com/form/projects, or open claude.ai/projects and try a multi-repo migration task.

Take for your setup
  • From the v1-endpoint example: add a final report «which PRs must merge first» to feature-build/task-lead for multi-repo tasks — add it?
  • From the complaint about seven subagents on a simple query: add a cap on parallel workers and a cost estimate before launch to the subagents skill or a hook?
  • Join the waitlist at claude.com/form/projects: try the shared project memory on one real task and compare it with our tasks/<slug>/context.md

Agweb: a WebKit browser for macOS that agents drive from the shell without stealing focus

Agweb is a single window on system WebKit (macOS 26+) that agents drive through an `agweb` command modeled on playwright-cli. The author ran several agents at once; Playwright's Chrome windows stole keyboard focus, and headless got blocked by some sites. Each agent gets its own workspace (`-w`) with its own tabs, and a dashboard (⌘D) shows every agent's tabs and last command. Clicks and typing are native macOS events. A named profile (`-p work`) keeps logins and can be shared. Each action's reply says what changed (network, lines, dialogs, downloads, console errors), so a second snapshot is usually unnecessary; there are also `snapshot --diff`, `find`, `text` (article as markdown) and `video-start` (MP4 recording). `fill --secret-cmd` types a password from the 1Password/Bitwarden CLI without exposing it to the agent; `ask` hands the tab to the human for MFA or CAPTCHA. Five idle pages: 590 MB and 0% CPU versus 1.6 GB for Playwright Chrome. Limits: WebKit only, no CDP, `route` mocks only fetch/XHR, some YouTube ads get through. On HN people criticized the lack of Linux and the shared profile: one agent logging out breaks the others.

You already have Claude in Chrome and Playwright scripts (Avito). What's new is parallel agents with no focus stealing and no shared window, diff-style replies that save tokens, and hidden secrets. First step: download Agweb.dmg from the Releases of paul-nameless/agweb, then from the Help menu install the CLI and the Claude Code skill (or run `agweb install-cli` and `agweb install-skill`), and try `agweb -w task open <url>` and `agweb -w task snapshot`.

Take for your setup
  • Try agweb instead of Playwright in the Avito scripts: one `-w` workspace per agent, no Chrome windows popping up over your work
  • Use `fill --secret-cmd` for browser logins alongside the secrets skill, so the password never reaches the transcript
  • Borrow the pattern of action replies that include a diff of changes, and `ask` (hand the tab to the human for MFA/CAPTCHA), in our browser skills
  • Run `agweb install-skill` and compare the installed skill with our browser-use skill

Floorplan: плагин для Claude Code и Codex рисует интерактивную карту кодовой базы простым языком

Floorplan (haydenschmitty/floorplan, MIT, v0.2.2, создан 27.10.2026, 306 звёзд) — плагин для Claude Code и Codex. Скрипты на чистом Node 18+ без зависимостей собирают файлы, импорты, роуты и веб-запросы; Claude или Codex решает, из каких частей состоит приложение, и описывает каждый файл. Результат — floorplan/index.html: зумируемая карта от всего приложения до одного файла, связи фронтенд-запросов с серверными эндпоинтами (в том числе между репозиториями), вид «от экрана», Ask-строка (отвечает мини-картой и пошаговым разбором), Health check (захардкоженные секреты — показывает где, не значения; эндпоинты без авторизации; неиспользуемые и слишком большие файлы, к каждому есть fix-промпт) и доска Recent work с тем, что изменил ИИ. При обновлении перечитываются только изменённые файлы, большие проекты делятся между параллельными помощниками. API-ключи не нужны, работает на вашей подписке. Папка floorplan/ и секция в CLAUDE.local.md не коммитятся; код, .gitignore и CLAUDE.md не трогаются. Правки architecture.json и descriptions/ переживают обновления. Аналитики нет, сервер слушает только локально.

У тебя уже есть codebase-memory MCP, скилл code-investigation и артефакты; Floorplan — это скорее визуальный слой для человека, а не память для агента. Новое: Health check с готовыми fix-промптами и сопоставление фронт-запросов с эндпоинтами. Ограничение: Ask-строке нужен Claude Code CLI. Первый шаг: `claude plugin marketplace add haydenschmitty/floorplan`, затем `claude plugin install floorplan@floorplan`, новая сессия и фраза «Make me a floorplan of this app».

Что взять себе
  • Поставить плагин на один проект и сравнить его Health check (секреты, эндпоинты без авторизации, неиспользуемые файлы) с нашим /code-review: что он находит дополнительно?
  • Взять идею «fix-промпт к каждой находке» в наш скилл code-investigation или observability: находка сразу превращается в готовое задание для субагента.
  • Попробовать запрос «If I change the users table, what breaks?» как шаблон для анализа влияния изменений перед feature-build и сравнить с ответами codebase-memory.
  • Перенять приём «сгенерированное не коммитим»: писать артефакты в CLAUDE.local.md и папку, которая сама себя игнорирует, чтобы не трогать общий CLAUDE.md.

RudderStack открыла DevBox: автономный агент «тикет → draft PR», по одной песочнице на задачу и без реальных ключей внутри

DevBox (MIT, rudderlabs/devbox, репозиторий создан 27.10.2026) — харнесс, который вы поднимаете у себя: даёте тикет, он планирует, пишет код, гоняет тесты, ревьюит свой diff и открывает draft PR. RudderStack заявляет, что мержит около 35% своих внутренних PR, merge rate 80%. Конвейер: orientation → planning → plan review (гейт: код не пишется, пока план не прошёл) → implementation → self-review → draft PR с «knowledge commit».

Архитектура: control-plane (хранит задачи, поднимает по одной песочнице на задачу через OpenSandbox, LLM не вызывает), harness внутри песочницы на DeepAgents и iron-proxy между песочницей и GitHub/LLM. В песочнице лежат только заглушки токенов, прокси подменяет их на настоящие на выходе и разрешает запись только в перечисленные репозитории. Ключи хранятся в Keychain/libsecret или в env. Комментарии в PR читаются только от доверенных пользователей (по умолчанию список пуст). Поддержаны OpenAI Responses API и Anthropic Messages API, модель и effort задаются по этапам. Только GitHub; задачи берутся из CLI и Linear; в main не пушит и не мержит. Нужны Docker с 8 ГБ, Bun 1.4.4+, установка около 15 минут.

Для вас пересечение с Workflow, субагентами и worktree большое, нового тут два: схема «заглушка токена в песочнице, реальный ключ подставляет egress-прокси» и жёсткий гейт ревью плана перед кодом. Ваш скилл secrets решает похожую задачу на стороне Keychain, но не изоляцию. Первый шаг: git clone https://github.com/rudderlabs/devbox.git, cp devbox.config.example.json devbox.config.json, bun run quickstart, затем bun run devbox create "Add a /health endpoint to your-org/your-repo".

Что взять себе
  • Секреты через прокси: для headless-запусков `claude -p` и ботов отдавать агенту только токен-заглушку, а настоящий подставлять на egress-прокси с белым списком репозиториев на запись — добавить это как вариант в скилл secrets?
  • Гейт плана: в feature-build не начинать implementation, пока отдельный ревьюер не пропустил план (как plan review в DevBox) — сделать это жёстким условием, а не рекомендацией?
  • Доверенный список авторов: если бот читает комментарии в PR/чатах, принимать только от явного allowlist, по умолчанию пустого — добавить в правила бота?
  • Knowledge commit: к draft PR добавлять отдельный коммит с выводами по задаче — попробовать в task-context как финальный шаг?

Ryugi: форк Superpowers, где агент рисует макеты UI и согласует их в браузере до спеки и TDD

Ryugi (流儀) — workflow-плагин для кодинг-агентов, форк Superpowers v7.0.0. Цепочка: brainstorm → макеты → спека → TDD → verify; скиллы срабатывают сами. Идея: агент не описывает UI словами, а показывает. Artboard — несколько вариантов дизайна рядом, их можно комментировать, отвечать в терминале (`q1 → b`). Document — дизайн-док с диаграммами, таблицами и кодом: комментарии к предложениям, правки на месте сливаются с правками агента. HTML — одностраничные прототипы с ползунками, значения контролов сохраняются, когда агент переписывает страницу. Verify — скриншоты собранной реализации рядом с утверждённым дизайном: принять или отклонить, отклонённое возвращается исправленным. Library — локальный браузер артефактов: `npx ryugi-artifacts`. Ставится в Claude Code, Gemini CLI, Codex, Cursor, OpenCode и ещё ~10 harness. Лицензия: скиллы MIT, приложение artifacts — AGPL-3.0. Репо создан 19.10.2026, 207 звёзд, 352 коммита. Подробности про спеку, TDD и субагентов на странице не раскрыты (они в docs/workflow.md).

У тебя уже есть superpowers, review-page, feature-build и plannotator, так что сам цикл «брейншторм → спека → TDD» знаком. Новое здесь — визуальный слой: сравнение вариантов UI рядом, комментарии по фрагментам и финальная сверка скриншота с утверждённым макетом. Первый шаг: `/plugin marketplace add Innei/ryugi`, затем `/plugin install ryugi@ryugi-dev` и в тестовом проекте написать `Let's make a react todo list`. Либо просто запусти `npx ryugi-artifacts` и посмотри библиотеку.

Что взять себе
  • Добавить в feature-build/review-page этап Verify: скриншот реализации рядом с утверждённым макетом, принять или отклонить, как в Ryugi.
  • Для UI-задач показывать в review-page 2-3 варианта дизайна рядом с ответом вида `q1 → b` в терминале вместо текстового описания.
  • Попробовать `npx ryugi-artifacts` как локальную библиотеку артефактов и сравнить с нашими Artifacts и backlog-hub.

Скилл /effects для Claude Code: накладывает эффекты на говорящую голову с трекингом лица, слои уходят за голову

Репозиторий Vibha-Ramprakash/claude-video-effects (MIT, 309 звёзд, 7 коммитов, создан 22.10.2026) — это один скилл для Claude Code. Кидаешь в чат вертикальное видео с собой в кадре и пишешь, например, `/effects orbit from 3 to 6 seconds`. Claude смотрит несколько кадров, составляет план на утверждение, потом рендерит `yourvideo_effects.mp4` рядом с оригиналом, звук не трогает. В заголовке репо «36 эффектов», в README — 45 (orbit, spotlight, comment-box, glass-widgets, tier-list, match-cut и др.); эффекты можно стекать в одном запросе, время задаётся словами, в том числе по фразе из речи.

Под капотом: трекинг лица OpenCV YuNet, вырезание человека MediaPipe Selfie Segmenter (отсюда слои «за головой»), ffmpeg и Python, 1080p по умолчанию, 4K по запросу. Модели лежат в `models/`, скрипты в `scripts/`, шрифты с лицензиями в `fonts/`. Цифры для графиков и счётчиков нужно давать свои; для orbit, noise, phone-fan, profile-wall нужна папка скриншотов. Звука и субтитров нет.

Для тебя это не новая механика (скиллы, Remotion и montage у тебя есть), а готовый образец скилла-пайплайна: SKILL.md + скрипты + модели в одном репо, «план на утверждение → рендер». Пригодится как источник приёмов трекинга и маски человека для Remotion. Первый шаг: `git clone https://github.com/Vibha-Ramprakash/claude-video-effects ~/.claude/skills/effects`, перезапустить Claude Code и прогнать `/effects orbit` на коротком клипе.

Что взять себе
  • Взять из репо связку YuNet + MediaPipe Selfie Segmenter и добавить в наш Remotion-пайплайн слой «текст за головой» как отдельный шаг в скилле montage?
  • Скопировать структуру скилла (SKILL.md + scripts/ + models/ + fonts/ в одном репо, автоустановка зависимостей при первом запуске) для наших скиллов с тяжёлыми зависимостями?
  • Перенять шаг «Claude смотрит несколько кадров и показывает план на утверждение до рендера» в скилл montage перед дорогим рендером?

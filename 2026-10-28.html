Kinetograph: рендер видео на Rust/GPU без Chrome, совместим с Remotion, есть MCP

Kinetograph (v0.2.0, Beta, репозиторий создан 2026-10-23, 234 звезды) - движок программного видео для агентов. Видео пишется на TypeScript с API Remotion (плюс CSS, SVG, Canvas 2D, WebGL, Web Audio). Импорты `remotion` и `@remotion/*` подменяются собственной реализацией, поэтому готовые Remotion-проекты должны идти без правок. Node гоняет код проекта и строит дерево кадра, а Rust-аддон (napi-rs, wgpu + Skia, FFmpeg) рисует кадры на GPU. По README пиксели не попадают в JS, Chrome для рендера не нужен. Цифры на Apple M4 с `--concurrency 4`: вертикальный ролик 33 с (988 кадров) - 24 с, 37 с в 1080p - 13 с, launch-фильм на 1184 кадра со звуком - 26 с. Каждая команда принимает `--json`, есть `still`, `strip` (раскадровка), `inspect --frame N --json`, `studio` и `mcp`. Лицензия PolyForm Small Business (бесплатно для компаний меньше 100 человек и дохода до 1 млн USD), API может меняться.

У тебя уже есть Remotion-пайплайн и MCP, так что новое здесь - замена Chrome-рендера на нативный и интерфейс, рассчитанный на агента: `still`/`strip`/`inspect` дают агенту посмотреть кадр и дерево сцены без полного рендера. Studio выделяет слои и шлёт агенту выбор, исходные места и скриншот области по ACP; проверен только Claude Code. Первый шаг: на macOS `brew install ffmpeg pkgconf`, собрать репозиторий (`npm ci && npm run build`) и прогнать один из твоих Remotion-проектов через `npx kinetograph render <index.tsx> --concurrency 4 -o out/x.mp4`, сравнив время и результат с текущим рендером.

Что взять себе
  • Прогнать один из наших Remotion-проектов через `npx kinetograph render ... --concurrency 4` и сравнить время и вывод с текущим рендером - стоит ли переходить?
  • Добавить в видео-скилл шаг самопроверки агента: `kinetograph strip -n 12` и `inspect --frame N --json` вместо полного рендера на каждую правку.
  • Подключить `npx kinetograph mcp` как MCP-сервер к монтажному проекту и посмотреть, заменяет ли он наши скрипты рендера.

Автор запустил офлайн-агента OpenCode + Ollama + Qwen3.5 9B на Mac и починил баг без сети

Статья Rittika Jindal (Latent Space, 27.10.2026): кодинг-агент полностью на ноутбуке без интернета, потому что в предгорьях Гималаев часто пропадает связь. Стек: OpenCode 1.19.4 (агент), Ollama (сервер модели), qwen3.5:9b (загрузка около 6,6–7,6 ГБ; по оценке нужно 12–16 ГБ RAM, а при контексте 64k может понадобиться больше). Ollama запускается так: OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 OLLAMA_CONTEXT_LENGTH=65536 ollama serve. OpenCode стартует с --pure (без внешних плагинов). В opencode.json model и small_model указывают на локальную модель, baseURL равен http://127.0.0.1:11434/v1, веб-инструменты закрыты, правки и shell идут через запрос разрешения. По карточке Qwen, 9B даёт LiveCodeBench v6 65.6 и BFCL-V4 66.1 (у 4B: 55.8 и 50.3). Это цифры из карточки модели, а не замеры на ноутбуке.

Проверка скромная: однострочный баг в expense_total.py (надо total += Decimal(amount)), 3 из 5 тестов падали, после правки прошли все 5, тесты агент не менял. Скорость не измерена, крупные репозитории не пробовали. Агент предложил pytest вместо unittest, поэтому автор советует называть точную команду тестов. Это запасной режим без сети, а не замена Claude Code; opencode и локальные модели на MLX у тебя уже есть, так что нового мало. Первый шаг: ollama pull qwen3.5:9b, поднять ollama serve с флагами выше, отключить Wi-Fi и проверить curl --noproxy '*' --fail http://127.0.0.1:11434/api/tags. Конфиг лежит в репозитории RittikaJ/opencode-qwen-local-setup.

Что взять себе
  • Скопировать из репозитория RittikaJ/opencode-qwen-local-setup opencode.json (локальный провайдер, закрытые веб-инструменты, запрос разрешений) как офлайн-профиль для opencode?
  • Автор проверял офлайн-режим двумя curl: к 127.0.0.1:11434/api/tags должен отвечать, к example.com должен падать. Добавить такую проверку в скилл или скрипт запуска локальной модели?
  • Агент взял pytest вместо unittest. Добавить в CLAUDE.md проектов явную команду тестов и правило «не менять тесты, ничего не устанавливать» в промпты для слабых локальных моделей?
  • Прогнать qwen3.5:9b через Ollama в нашем скилле vendor-review как бесплатного ревьюера без сети?

03ty releases28.10

ty 0.0.93: в preview появились baseline-файлы диагностик, плюс исправления паники и зависания

ty — type checker для Python от Astral (авторы ruff и uv). В релизе 0.0.93 от 2026-10-28 главное — preview-функция diagnostic baselines (#27636): она помогает внедрить ty в проект, где уже есть ошибки. В pyproject.toml задаёшь [tool.ty] baseline = "ty-baseline.json", а командой ty check --update-baseline записываешь текущие диагностики. Дальше совпадающие с baseline диагностики убираются из вывода CLI, а в language server показываются как подсказки (hints). Формат файла в preview может измениться.

Остальное — исправления. Починена паника при проверке truthiness в цикле (#29759) и зависание при отрицании рекурсивных union из instance-типов (#29652). Поправлены сужение типов строк и int при сравнении с членами enum (#29743), сужение после guard в match (#29558), @override на реализациях overload в stub-файлах (#29470), объединение ограничений у повторяющихся ParamSpec (#29172), а также не создаётся синтетический первичный ключ для абстрактных Django-моделей (#29744). Есть ряд оптимизаций скорости: match по большим union, длинные булевы выражения, а Linux x86-64 сборки оптимизированы через LLVM BOLT.

Для твоего стека (FastAPI, Pydantic, SQLAlchemy) baseline полезен, если подключаешь ty к старому сервису: CI падает только на новых ошибках, а старый долг не блокирует. Первый шаг: обновить ty до 0.0.93, добавить baseline в [tool.ty], выполнить ty check --update-baseline и закоммитить ty-baseline.json. Раз формат может измениться, после обновления ty файл придётся пересоздать.

Что взять себе

  • Добавить в CI шаг ty check, который падает только на новых диагностиках сверх baseline - настроить?
  • Закрепить версию ty (0.0.93) в dev-зависимостях и пересоздавать baseline при обновлении, так как формат в preview может поменяться - добавить это правило в README проекта?
